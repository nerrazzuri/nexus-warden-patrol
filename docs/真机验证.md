- **只有这一张表。** 新的真机项加在这里（对应那一节的末尾，接着编号）；做完在这里改「结论」那一格。不再另开清单。
- **某一天的测试单**（比如 `真机测试单-2026-11-10-新机静态.md`）只排顺序、写怎么摆场，项目用这里的编号；结果回填到这里。
- **旧的都在归档里**：`docs/归档/真机验证/`。旧总表（810 条，到 2026-11-14）、10-29 两张、11-05 两张、W57 周一卡、10-28 分拣提议。旧总表里做完的 192 条留在那里当记录，这里不再列。「原编号」一栏写着每一行是从旧表哪几条来的。
- 过期不用再做的有哪些、为什么，见文末「附：这次去掉的」。

**结论怎么写**：✅ 真机：结果（日期）／❌ 没过：怎么没过、进了哪张工单（日期）／◐ 做了一半：做了什么、剩下什么／⬜ 没做／— 不用做：原因。演示站点上做完、成功了也算做完（用户 2026-10-28），写「✅ 演示站点：…」。

**数一数**：`python3 tools/field_pending.py`（每一节的合计），加 `--list` 把没做完的一条条列出来。

**动机器人的规矩**（照旧）：

- 「要什么」一栏写着「动」的，要用户在场。
- 同一条路线、同样的安全条件，可以按测试卡一次批准、连着跑；站起、趴下、每一批的第一趟还是单独问。
- 有异常（定位丢、跑偏、碰到东西、换地方）马上停、重新问。
- 每批开始前核对：档位低速、谁拿着控制权、手持遥控器在谁手上；急停有人守。
- 日志放 `runs/field-logs/`；PIN、口令、开通码不进日志。

「要什么」的写法：**动** = 机器人要走（用户在场）；**站** = 站着或趴着不走；**站点主机** = 要一台装好的站点主机（不是笔记本临时起的）；**手机** = 真手机；**上装 V2**、**充电桩**、**第二台** = 要那样东西到场。
