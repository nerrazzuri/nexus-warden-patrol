# W78 过玻璃门（设计，2026-11-21）

>
> **状态：只有设计，还没写代码。**

## 一、问题

- **激光看不清玻璃。** 门关着时，激光多半直接穿过去，规划以为是空地。门开着也是空地。所以只靠激光，分不出开和关。
  10-19 C40221 撞玻璃门那次，厂家避障也没触发（`docs/事故-20261019-C40221-撞玻璃门.md`）。
- **现在能做的只有「封死」。** 网页上在玻璃墙、玻璃门的位置画虚拟墙或障碍，机器人会绕开；但门开着也过不去。
- **现在的 YOLOX 认不出门。** 机器人上的 `yolox_s.onnx` 是官方的 COCO 模型，80 类里没有「门」。我们只用了「人」这一类。

## 二、做法总览

1. 地图上标「门」（新的区域种类）。没确认开着，机器人就把它当墙。
2. 路线穿过门时，机器人先停在门前，确认门开着才过，过完把门恢复成墙。
3. 门开没开，用相机（训练一版认「开 / 关」的 YOLOX）和激光一起判断。拿不准就不过。
4. 不同的门分开处理：
   - 感应自动门：等它开；
   - 要人推的门：叫人来开；
   - 旋转门：不过。

## 三、地图上标门

- **新的区域种类 `door`。** 跟虚拟墙一样，在门洞上画一条线，站点按线算成一条窄带（`WALL_WIDTH_M` 0.3 m）。
  - 对机器人来说，平时就是一条禁行带：规划不穿、每拍回退检查照守。
  - 不同的是它知道这是门，可以按第四节的流程「开一下」。
- **门的属性：**

  | 属性 | 取值 | 缺省 |
  |---|---|---|
  | 种类 | 感应自动门 / 手动门（机器人过不了）/ 常开（当普通通道，只在门前减速）/ 旋转门（不过） | 感应自动门 |
  | 最长等多久 | 秒 | 自动门 15 s，手动门 60 s |
  | 门洞宽 | 站点按画的线算 | — |

- **种类按方向分**（真机 11-24 办公室去商场那扇玻璃门）：从商场一侧走近会自动开；从办公室一侧不会，要按门边的开门按钮。
  所以「种类」和「最长等多久」按两个方向各记一份：画门线时站点认出线的两侧（A 侧、B 侧），每侧一套属性，缺省两侧一样。
  - 按钮开门那一侧，V1 当手动门处理（叫值守来按）；以后接门禁（V2 第三批）：开门按钮一般是干接点，可以并一个继电器让机器人自己开，
    要先看清按钮的型号和接线。
- **门洞宽度检查。** 按窄通道标准：机身 1.03 × 0.58 m，每边至少留 0.2 m，所以门洞要不小于 0.98 m。
  不够宽的，画的时候就提示「机器人过不去」，存成普通虚拟墙。
- **老机器人。** 站点发给不认 `door` 的机器人时，换成同一块禁行区，跟 `erase_as_nogo` 一样的做法。这样对老机器人是一样严：门永远关着。
- **收紧和放宽怎么算：**
  - 加一扇门算收紧：原来能走，现在要停下确认。
  - 把禁行区或虚拟墙改成门，算放宽：原来过不去，现在能过，要人确认。
  - 门的种类从「手动」改成「自动」，也算放宽。
- **以后（第二批）：** 建图时自动找门。沿建图路线，相机认出门的地方、激光墙线上的缺口，列成候选，工程师在地图编辑页确认。

## 四、路线过门

1. **规划。** 路线穿过某扇门时，这段在门两侧拆开：
   - 进门点：门线前 1.0 m，正对门；
   - 出门点：门线后 1.0 m。

   不穿门的路线照旧。路线检查遇到「穿过手动门」和「穿过旋转门」时，提示改路线。
2. **到进门点停下，查门**（第五节）。
3. **开着：**
   - 只把这扇门的禁行带撤掉，限时 20 s。Nav2 的禁行掩膜和代理每拍的检查一起撤。
   - 走到出门点，门里限速 0.3 m/s，禁行带立刻恢复。
   - 过门途中相机继续看：看到门扇在动（自动门开始关），当场停下，退回进门点重新查。
4. **关着：**
   - 自动门：每 0.5 s 查一次，最多等「最长等多久」。
   - 手动门：给值守发一条「请开门」，带门前照片，位置标在地图上。
   - 等不到：报「门没开」，按到不了的点处理（现有的跳过 / 结束流程），这趟不再试这扇门。
5. **拿不准**（相机和激光说法不一）：当关着处理。宁可多等，不撞。

## 五、判断门开没开

- **相机（主）。**
  - 用 YOLOX-s 再训练一版，分 `door_open`、`door_closed` 两类，普通门、玻璃门都在里面。
  - 只在门前查的时候跑，不常开，跟认人的模型分开，不动已经验过的认人模型。
  - 在 Orin 的 GPU 上，跟认人同一套 onnxruntime，一帧约 26 ms。
  - 每次查拍 5 帧（约 0.5 s），5 帧里至少 4 帧认成开着、分数 ≥ 0.6，才算开着。
  - 位置要对得上：认出的门框所在方向（按相机标定，跟认人测距用的同一套），跟地图上门线的方向差在 10° 以内。不在门的位置的「门」不算。
- **激光（否决）。**
  - 门的禁行带里，0.1–1.8 m 高度有东西（人、推车、门扇），就不过。
  - 激光不用来判断「开着」：关着的玻璃常常也打不出点。
- **热像（待验）。** 玻璃挡长波红外。关着的玻璃门在热像里是一整块反光面，开着才看得到门后的东西。
  机器人有热像镜头的话，这可能是比可见光还准的线索。27 号一起录，看能不能用。
- **规则：** 相机说开着，并且激光没有否决，才过。其余一律当关着。
- **晚上：**
  - 灯暗的地方，可见光会认不出，按拿不准处理，只等不过。
  - 热像不受光线影响，验好了可以补上。

## 六、模型怎么训

- **数据：**
  - Open Images V7 的「Door」类（另有「Door handle」）。标注是 CC BY 4.0，图片是 CC BY 2.0，商用要注明出处，记进 `tools/third_party.py` 的清单。
  - 它不分开、关，只用来学「门长什么样」。
  - 「开 / 关」主要靠我们自己现场录的数据（第八节）。
  - 自己的数据先用 Grounding DINO 或 OWLv2（都是 Apache-2.0）在台式机上自动框门，人工过一遍，再标开、关。
  - YOLO-World 是 GPL-3.0，不用。
- **训练：**
  - YOLOX 官方训练代码（Apache-2.0），从 COCO 的 `yolox_s` 权重接着训，输入 640。
  - 台式机 RTX 4060（8 GB）上训，约一天出第一版，导出 ONNX。
- **验收**（27 号录的、没拿去训练的那部分，按「一次查门」算，5 帧投票之后）：
  - 关着的门判成开着：≤ 1%。这是会撞的那一边。
  - 开着的门判成关着：≤ 10%。只是多等，不危险。
  - 达不到就不上机器人，先补数据。

## 八、27 号现场要录的（玻璃门 + 带回来的数据）

**录什么话题**（一个包里同时有相机和激光，这样训相机、核激光用的是同一时刻）：

```bash
source /opt/ros/humble/setup.bash
export RMW_IMPLEMENTATION=rmw_zenoh_cpp ROS_DOMAIN_ID=24     # 不加录不到厂家的话题(笔记本 11-23 试录)
ros2 bag record -s mcap -o ~/nexwar_bags/glass-<门号>-<状态>-<序号> \
    /front_camera/image_compressed /rear_camera/image_compressed \
    /front_lidar /rear_lidar /front_lidar/imu /tf /tf_static
```

- 热像是网络摄像头，不在 ROS 话题里。地址在机器人的 `payload.json` 里，别抄到聊天里，里面有口令。
  有热像的话，用笔记本另录一份：`ffmpeg -rtsp_transport tcp -i <热像地址> -c copy glass-<门号>-<状态>-<序号>-thermal.mp4`。
- **别在机器人自己巡逻的时候录。** 11-20 录大包时，代理的循环卡过 10–20 s；修好的那版（`345998e1`）可能还没装上。
  录的时候用遥控器慢慢开，或者让它站着。每段不超过 2 分钟。
- **磁盘：** 前后两个雷达加相机，约 45 MB/s（11-23 试录 30 s 是 1.3 GiB，7 个话题都在），2 分钟约 5–6 GB。录之前先看剩多少。
- **时间戳：** 相机和雷达的 `header.stamp` 用的是 RK3588 的钟（11-23 比实际慢约 230 天），两者之间对得上；跟 Orin 上的东西对齐用 mcap 里记的收到时间。
- **只拍同意出镜的人**（跟 I01 一样）。

**每扇门录这几种**（至少 3 扇不同的玻璃门，再加 1–2 扇普通门当对照）：

| 状态 | 怎么录 | 每段 |
|---|---|---|
| 关着 | 机器人正对门，从 3 m 慢慢走到 1 m；再从左、右各斜 30° 各来一次 | 20–30 s |
| 全开 | 同上 | 20–30 s |
| 正在开、正在关 | 走向感应门，让它自己开，走过去，它在身后关上（后相机也在录） | 一次到底 |
| 半开 | 手动门推开一半 | 20 s |
| 有人进出 | 门开着，有人从门里走过 | 20 s |
| 灯暗（能做就做） | 晚上或关灯，关着、开着各一段 | 20 s |

- **包名就是标签：** `glass-<门号>-<closed|open|moving|half|people|dark>-<序号>`。门号从 1 开始编。每扇门再用手机拍一张照，记下它在地图上大概哪里。
- **同一天顺带：** 建完图后，把站点上留的关键帧拷回来（`<站点数据目录>/mapkf-keep/<机器人>/<图>/<版本>/`，站点只留最近 5 份，建完就拷），
  回来跑回环对照 `tools/lc_try.py`（`docs/建图回环.md` 第七节）。
  - 现场有楼梯的话，录一段上下楼（真机验证 D19，多楼层第一步）。
  - 厂家超声：11-23 测过（真机验证 F34–F37），两个探头朝**正侧面**，看不到正前方的门，不用加进录包话题。

## 九、不做的、没验过的

- 旋转门、要刷卡的门：不过（门禁联动在 V2 第三批）。
- 双开门只开一扇：门洞按开的那一扇算宽度，够宽才过。现在的流程不分这种情况，当关着处理。
- 玻璃墙紧挨着玻璃门：墙那一段照旧画虚拟墙，只有门那一段画门。
- 自动门在机器人走到一半时关上：靠门自带的防夹，加上我们过门途中一直在看的相机。真机第 4 步要专门试。
