# 1.1-7 随机巡逻 设计

2026-11-28。路标 `docs/1.1-路标.md` 1.1-7。

## 现在已经有的（W14，10-02）

- 值守方案每一条有个勾「随机起点和方向」（`shuffle`）：每一圈从随机一个点开始，一半概率反着走。点的先后不打乱成乱跳 —— 路线还是那条路线，不多走冤枉路（`guard_duty._lap_points`）。
- 默认不勾；只在网页「布防 → 值守方案」里能勾，布防向导里看不到。
- 每一圈之间的间隔（`gap_min`）是固定的：跑完一圈歇 N 分钟，准点出发。

所以现在想摸规律的人，看一晚上就知道「每 20 分钟来一次」。

## 要加的

1. **每圈间隔随机**：勾了随机、间隔设了 N 分钟（N ≥ 2）的，每一圈实际歇 N 的 50%–150% 之间随机一个数（平均还是 N）。
   - **不超过防区的最长间隔**：值守方案里给防区设的「最长多久没人看」照样管着。随机出来的间隔会让某个防区超过上限的，就取不超的那个最大值。方案检查（`forecast`）按 1.5 N 算最坏情况：原来能过、按 1.5 N 不过的方案，检查时提示「开了随机，最坏 X 分钟才看一次 Y 区」，不拦。
   - 间隔 0（跑完马上下一圈）不加随机。W74 加密巡查（看见人以后每圈不歇）也不加。
2. **布防向导里露出来**：向导「值守」那一步加同一个勾，写「随机起点、方向和间隔（不让人摸清规律）」。
3. **新方案默认勾上**；已经存着的方案不动（客户自己定的不替他改）。
4. **记录写清楚**：值守记录每一圈开始时写「随机：从 C 开始、反向，歇了 14 分钟（设的 20）」，主管看记录知道不是机器人乱跑。

不改的：点的先后不全打乱（全打乱会来回穿场，多走一倍路、电也多耗）；不动导航。

## 测试

- 站点：随机间隔落在 50%–150%、平均接近 N；超防区上限时被截住；间隔 0、加密巡查不随机；旧方案读出来 `shuffle` 不变、新方案默认 true；记录里有起点、方向、实际间隔。
- 网页：向导里的勾、默认勾上；方案页文字改成「随机起点、方向和间隔」。
- 不动 App（App 不编辑值守方案）。

粗估 1–2 天。
