# 公司后台 一期 方案（W43）

> 2026-11-21 用户定：**一期只做证书相关**；**根钥匙留在台式机，后台只拿中间钥匙**。
> **放在哪台机器上跑：未定**（用户「我再想想」，见第七节）。不影响先写代码、在办公室内网试。

## 一、为什么做

现在要签证书和解绑令，都得在台式机上手工操作：

- **出厂证书**（W63）：开发样机、修过的板子补身份，要把申请 JSON 贴进聊天，台式机签好再贴回去
  （`docs/出厂流程.md` 第三节）。
- **解绑令**（W42）：客户站点主机坏了、没备份，机器人解不了绑，只能找公司值班的人在离线机器上签
  （`docs/狗绑定与解绑-设计要点.md` 第 3 条）。
- **出厂台账**：在台式机的一个 CSV 里，只有一个人看得到。

一期要做到：工程师在外面也能**自己申请**、按权限**马上拿到**证书或解绑令，每一张都有记录。
同时根钥匙永远不上网。

## 二、一期做什么、不做什么

**做**

1. **公司员工账号**：管理员、工程师、生产线三种角色。登录要密码 + 手机验证码（TOTP），
   签证书的权限比照站点上的账号来管。
2. **设备登记表**：每台机器人的序列号、型号、芯片编号、设备公钥、出厂证书、哪天出厂、卖给了谁（手填）、
   备注。先把台式机上的 `出厂台账.csv` 导进来。
3. **签出厂证书**：传 `device-request.json` 上来（网页上传，或从工程师 App 上传），后台核一遍、签好、
   记进登记表，给回证书文件。同一序列号换了设备钥匙或芯片编号，要管理员批准（这就是换过主板）。
4. **签解绑令**：工程师填序列号和原因，后台签一张**只对这一台、24 小时、一次作废**的解绑令，
   给回文字和二维码。以后要主管审批的话，加一个开关就行。
5. **作废名单**：中间钥匙丢了或换了，能把它作废。名单用根钥匙签，随发行包发到站点和机器人（第四节）。
6. **操作记录**：谁、什么时候、给哪台签了什么、为什么。只能加，不能删改。

**一期不做**（以后再加，见 `docs/V2-路标.md`）

- 站点自动上报被拒记录（`company-reports`）。一期先在网页上**手动上传**导出的文件。
- 客户账号、站点许可、到期、功能开关。
- 远程运维：站点心跳、看日志、推送升级包。
- 站点、机器人主动连后台。一期里**站点和机器人都不连后台**，只有员工的浏览器和 App 连。

## 三、钥匙怎么放

```
根钥匙（台式机，离线）                     中间钥匙（后台，一年）
  factory.key ──签──▶ 出厂中间钥匙证书 ──▶ 签每台的出厂证书
  unbind.key  ──签──▶ 解绑中间钥匙证书 ──▶ 签每张解绑令
```

- **根钥匙不动**：`factory.key`、`unbind.key` 留在台式机上，正式发行前照原计划挪进加密 U 盘
  （`docs/钥匙生成与保管.md`）。它们以后只干两件事：一年签一次中间钥匙，出事时签作废名单。
- **中间钥匙**在后台机器上生成，私钥不出后台。台式机签它的证书：写清楚公钥、用途（出厂或解绑，
  一把只管一样）、生效和到期时间（一年）、编号。
- **私钥加密存放**：后台每次启动要人输一次口令才能解开（跟站点的 secrets 密钥一样处理）。
  机器被拿走、硬盘被拷走，拿不到能用的私钥。
- **到期前换**：到期前 30 天后台报警。台式机签一把新的，新旧重叠一段时间。
- **后台被攻破**时：用根钥匙签一份作废名单，把那把中间钥匙作废，再签一把新的。已经出厂的机器人、
  已经签好的证书都不用动，只要不是作废之后签的。为了这一点，每张证书都写签发时间，作废名单写「从什么时候起不认」。

**跟现在的对比**：现在根钥匙直接签每一张。中间钥匙是多出来的一层，丢了也有退路。

## 四、站点、机器人那头要改什么

现在的出厂证书是根钥匙直接签的（`nexwar_contract.device_id`，`v: 1`）；解绑令也是根钥匙直接签的
（`nexwar_contract.binding`）。

- **证书和解绑令里带上中间钥匙证书**（新格式 `v: 2`）。核的时候分两步：先用根公钥核中间钥匙证书
  （用途对、签发时在有效期内、没作废），再用中间钥匙核这一张。
- **老格式照样认**：`v: 1` 由根钥匙直接签。已经出厂的 C40221、C40011 不用重签。
- **作废名单**：放在 `/etc/nexwar_site/factory-pub.d/` 和机器人的解绑公钥目录旁边，随发行包更新。
  现在站点和机器人已经能认多把钥匙、作废其中一把（`factory_pubkeys`、`_unbind_keys`），
  只是还不认中间钥匙，这次补上。
- **要发版**：站点和机器人要升到认 `v: 2` 的版本，后台签出来的证书和解绑令它们才认。
  一期上线前要先发这一版。

## 五、怎么做

- **跟站点同一套**：Python 标准库的 HTTP 服务 + SQLite，新包 `packages/company-backend`。签名用现有的
  `nexwar_contract`（ed25519）。网页沿用 `web/console` 的样式，单独打一个小包。
- **工程师 App**：在现有 App 里加一个「公司」入口，申请解绑令、上传出厂申请。用公司账号登录，
  跟站点账号分开。
- **台式机工具**：加两条命令：`company issuer-sign`（签中间钥匙证书）、`company revoke-issuer`（签作废名单）。
  都离线运行。
- **上线前做外审**，重点看钥匙、权限、作废这三块。

## 六、分几步

| 步 | 内容 | 能独立验收 |
|---|---|---|
| 1 | 中间钥匙格式、`v: 2` 证书和解绑令、作废名单；站点和机器人认新格式（老的照认） | 单元测试 + 仿真站点 |
| 2 | 台式机命令：签中间钥匙证书、签作废名单 | 命令行 |
| 3 | 后台服务：员工账号 + TOTP、设备登记表（导入台账）、操作记录 | 内网网页 |
| 4 | 后台签出厂证书、签解绑令；网页上传申请、下载证书 | 内网走通：样机补身份 |
| 5 | App「公司」入口：申请解绑令、上传出厂申请 | 真机：解绑一台样机 |
| 6 | 外审，发站点和机器人认 `v: 2` 的版本 | 外审通过 |
| 7 | 上线到公网机器（等第七节定了） | — |

第 1～6 步在办公室内网就能做完、测完。

## 七、待定：放在哪台机器上跑

工程师在客户现场要申请解绑令，后台得在公网上连得到。这跟 11-21「先不搞公网」冲突
（`docs/外网站点-方案.md`）。几种做法：

- **办公室机器 + 公网 IP**：先查办公室宽带有没有固定公网 IP、能不能开端口。有的话不花钱，
  但办公室停电断网，后台也跟着停。
- **租 Contabo VPS**：一个月几欧元。后台机器在外面，所以中间钥匙「被攻破能作废」那套更要紧。
- **只在内网，外面走 VPN**：后台不对公网开，工程师手机先连公司 VPN（WireGuard，要新搭）。
  最安全，但工程师每次要多一步。

内网上测完（第 6 步）之前定下来就行。
