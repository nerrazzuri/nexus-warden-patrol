## 〇、A 方案：机器人自己走 4G（主）

```
 4G 随身 Wi-Fi ZTE U30 Air（绑在机器人上；切到 5 GHz，149 信道）
        │ Wi-Fi
 RK3588（厂家板）：wlan0 用厂家脚本临时连随身 Wi-Fi；热点 p2p0 同信道照开、不掉；它本来就做 NAT
        │ 机器人内网 192.168.168.0/24
 Orin（我们的代理，Tailscale 100.67.176.60）：默认路线临时指向 192.168.168.168
        │ 互联网（Tailscale：先经新加坡中转，几秒后变直连）
 站点笔记本（舞台边，插电；Tailscale 100.69.130.19；上网：会场 Wi-Fi，不行用手机 USB 共享）
        │ HDMI
       大屏
```

**11-23 实测**：
- 代理经 Tailscale 连上站点；切换时离线 8 s 自己回来。Tailscale ping 平均 90 ms，最高 526 ms；画面延迟约半秒。
- 原画经 4G 上行稳定 3.4–3.6 Mbit/s，这张 Maxis 卡上行只有约 3.2 Mbit/s，余量很小。站点的「省流量」**不降**这一段（它只管站点到浏览器）→ 机器人这头转小（PR #388，`--video-push-lite`）。
- 当时为了不改证书，用了借道：笔记本 advertise `192.168.234.232/32`，地址挂在 `lo` 上，Orin 开 accept-routes。画面一开始一直断：笔记本回包的源地址选成了 100.69.130.19，SRT 不认。临时改路由的源地址后画面才出来。**以后不借道**，直接连笔记本的 Tailscale 地址（下面第 3、4 步），这个问题就没有了。
- tailscale0 的 MTU 是 1280，画面照样能过（SRT 直接推到 100.69.130.19 马上就通）。

## 三、提前在办公室做好（一次）

需要 PR #374（省流量，`video.lite` 可配）装进随行笔记本的站点；没装的话第 3 步跳过、用原画。

1. **Tailscale 账号**：用公司账号建一个 tailnet，只加随行笔记本、舞台电脑（要的话再加一部手机）。
   管理页里打开 MagicDNS 和 HTTPS Certificates（`tailscale serve` 要用）。
2. **随行笔记本装 Tailscale、把站点网页挂出去**（只在 tailnet 里能开，**不要用 `tailscale funnel`**，那是对整个互联网开放）：

   ```bash
   curl -fsSL https://tailscale.com/install.sh | sh
   sudo tailscale up                       # 浏览器里登录公司账号
   sudo tailscale serve --bg https+insecure://127.0.0.1:8443
   tailscale serve status                  # 记下 https://<笔记本名>.<tailnet>.ts.net
   ```

   - `https+insecure`：Tailscale 到站点这一段不核站点自己的证书（站点证书是我们自己的 CA 签的，名字里有 127.0.0.1、192.168.234.232、`<主机名>.local`，没有 localhost，所以写 127.0.0.1）。舞台电脑看到的是 Tailscale 发的正规证书，不报警告。
   - 站点证书不用重签，手机不用重新添加站点，机器人不用动。
   - 网页画面走 WebSocket，站点要求 Origin 跟 Host 一样；资料说 `tailscale serve` 会把浏览器那边的 Host 原样带过去，彩排时确认（C18）。不行就用第五节的退路。
3. **大屏用的小画面**：随行笔记本 `/var/lib/nexwar_site/site.json` 加 `"video": {"lite": {"width": 960, "fps": 8, "q": 8}}`(11-23 笔记本上还没有 `video` 段;有的话在里面加 `lite`;改前 `sudo cp` 留一份)，重启站点（`sudo systemctl restart nexwar_site`）。
   - 一路大约 3 Mbit/s（原画 5 帧约 4 Mbit/s；缺省小画面 640 宽、2 帧约 0.3 Mbit/s）。彩排时按 C21 选定当天用哪一档。
   - 舞台电脑的网页：右上用户菜单 →「省流量」开。
4. **机器人热点那条连接：只核对，不改**（笔记本 11-22 查过）。
   - 用 **「XG2WIFI_C40221 1」**：固定 192.168.234.232/24、没有网关、绑自带网卡 wlp59s0、自动连，带一条 192.168.168.0/24 via 192.168.234.1（竞品上装那段）。它本来就是 never-default yes，所以上网不会走机器人热点。
   - **别用**同名不带「1」的「XG2WIFI_C40221」（DHCP、不自动连）：机器人上 `NEXWAR_SITE_MQTT`、`NEXWAR_SITE_NTP`、`NEXWAR_ROUTES` 都写死了 .232，笔记本地址一变机器人就连不上站点。
   - **别开**「capture-hotspot」（USB 网卡上的共享热点 192.168.234.1/24）：跟机器人热点同网段，会抢地址。

   ```bash
   nmcli -g ipv4.never-default,ipv4.addresses con show "XG2WIFI_C40221 1"   # 要是 yes 和 192.168.234.232/24
   ```

   插上手机、打开「USB 网络共享」以后核对（手机那块网卡这台按接口位置起名，多半叫 enp0s20f0uN，看 `ip route` 里 default 走的是哪块就行）：

   ```bash
   ip route        # default 走手机那块；192.168.234.0/24 走 wlp59s0
   ping -c3 192.168.234.1 && ping -c3 1.1.1.1
   ```

   - **当天关掉别的 Wi-Fi 自动连**（要用户点头）：这台存了 20 多个自动连的 Wi-Fi（旅馆、办公室……），热点一断，wlp59s0 可能自己连到别的网上去，机器人回来也连不回站点。先记下、再关，活动后照记下的改回（第六节）：

     ```bash
     nmcli -t -f NAME,TYPE,AUTOCONNECT con show | awk -F: '$2=="802-11-wireless" && $3=="yes" && $1!="XG2WIFI_C40221 1" {print $1}' > ~/wifi-autoconnect-1203.txt
     while IFS= read -r n; do sudo nmcli con modify "$n" connection.autoconnect no; done < ~/wifi-autoconnect-1203.txt
     ```

5. **舞台电脑**：装 Tailscale、登录同一个账号；浏览器打开第 2 步记下的地址，登录站点，进值班页，前摄像头全屏。

## 五、出事了怎么办

| 现象 | 先做什么 |
|---|---|
| 大屏卡住、画面不动 | 看随行笔记本网页：有画面 → 是 4G 那段，等它自己接上或换卡；没画面 → 是机器人热点那段，随行的人走近一点 |
| 舞台电脑打不开站点地址 | `tailscale status` 两边都在线吗；随行笔记本 `tailscale serve status` 还在吗 |
| 网页能开、画面一直黑（WebSocket 被拒） | 退路：舞台电脑直接开 `https://<随行笔记本的 Tailscale IP，100.x.y.z>:8443`，浏览器说证书不受信任，点「继续」 |
| 4G 很慢 | 换另一家的卡；站点的小画面降一档（640 宽、5 帧），重启站点 |
| 随行笔记本没电 / 睡着了 | 站点停了，大屏和手机都没画面；机器人照样用厂家遥控器开。插电、开盖，站点自己起来 |
| 机器人有异常 | 厂家遥控器停；我们的网络跟它没关系 |
