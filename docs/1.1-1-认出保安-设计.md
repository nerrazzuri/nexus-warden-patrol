# 1.1-1 认出保安 设计

2026-11-28。路标 `docs/1.1-路标.md` 1.1-1。

**用户 11-28 批：「你来给建议，按你建议定」**，三条定下来的写在最后「定下来的」。

## 要解决的事

11-13 POC：工厂夜里布防，保安照常在布防区走动，机器人每次看见他都报 P1。用户否了「保安打卡后这个防区静音 30 分钟」（谁都能趁这 30 分钟进来），要的是**机器人认得出这个人是保安**。

现在有的：「授权在场」（`authz.py`，网页「授权和临时撤防」）—— 名字 + 防区 + 星期 + 时段，时段里看见**任何人**都不报 P1，只记 P3。它不认人，所以只适合「维修工周六 9–12 点在 B 区」这种，不适合保安整夜巡。

## 两种认法，一起用

| | 人脸白名单 | 保安带手机靠近 |
|---|---|---|
| 怎么认 | 机器人相机拍到脸，跟登记过的保安比 | 保安手机上的 App 发蓝牙信号，机器人收到就知道附近有哪几个保安 |
| 能认多远 | 约 5 m 以内、要正脸（开工前实测） | 约 10–20 m，不分方向 |
| 夜里、背对 | 夜里要开聚光灯；背对认不出 | 不受影响 |
| 认得准不准 | 准：认的是这个人 | 只知道「附近有保安」，不知道画面里的是不是他 |
| 要什么 | 软件（模型跑在 Orin 上） | 机器人上加一个 USB 蓝牙接收器（几十块钱）；App 要后台常开蓝牙 |

**判定规矩**（核心，宁可多报不能漏报）：

1. 这一刻机器人看见的每一个人，都必须被认作保安，才不报 P1。有一个没认出来的 → 照 V1 流程报（W77 全自动处置）。
2. 人脸认出 = 这个人算保安。
3. 只有手机靠近、脸没认出：**不当没事，也不直接报 P1**。先发 P2 给附近那几个保安的手机：「机器人在 B 区看见一个人，是你吗？」带那一刻的截图，点「是我」就记 P3；**60 秒没人点 → 升 P1**，照 V1 流程处置。机器人这 60 秒里停下看着他（不开警笛）。
   - 为什么不按「人数 ≤ 手机数」放过：保安在机器人身后 15 m，前面来了一个陌生人，机器人看见 1 个人、附近 1 部保安手机 —— 按人数就漏报了。蓝牙只知道远近，不知道方向，对不上画面里是哪个人。
4. 认出来了也记一条 P3「保安 张三 经过 B 区」，主管在记录里看得到每个保安什么时候在哪。
5. 认作保安的那段时间里，机器人照常巡，不停下、不跟。

## 人脸

- **模型**：InsightFace 预训练模型只许非商用，不用。用 OpenCV Zoo 的 YuNet（人脸检测，MIT）+ SFace（识别，Apache-2.0），跑在 Orin 上，跟现在的人员检测同一个检测节点：人员检测框出人以后，只在框里找脸。
- **比对在哪**：检测节点只算出脸的特征值（一串数字，不是照片），连同「哪个人框、离多远」发给站点；**名单和比对都在站点**。机器人上不存名单 —— 机器人丢了、被拆了，也拿不到保安的人脸数据。
- **把握**：比对分数过高门槛才算认出；看不清、侧脸、太远一律当陌生人。门槛开工后用实测数据定。
- **登记**：管理员在网页或 App 上给保安拍 3–5 张正脸（App 用手机相机），本人在手机上勾「同意」，站点算出特征值，**原照片不留**。

## 手机靠近

- 保安登录 App、打开「我在值班」后，App 每隔几秒发一次蓝牙广播。广播内容是站点发给这部手机的、每 10 分钟换一次的随机码（外人录下来也只能用 10 分钟，也追踪不到是谁）。
- 机器人上的蓝牙接收器听到随机码 → 报给站点 → 站点查出是哪个保安、信号强度大概多远。
- **App 被划掉、手机锁屏**：安卓靠前台服务可以一直发（现在后台值守已经有前台服务）；iOS 后台发蓝牙受限，iOS 版出来后再看。
- **硬件要确认**：Orin 或上装板上有没有能用的蓝牙；没有就加 USB 接收器，装在机器人上面不被挡住的位置。

## 个人数据（马来西亚 PDPA）

- 只给自愿登记、在手机上勾了同意的保安建人脸资料；随时可以撤销，撤销当场删掉特征值。
- 站点上特征值加密存（跟现在站点的密钥同一套），不存原照片，不出站点。
- 谁登记、谁删、谁看了「保安经过」的记录，都进审计。
- 客户在现场贴告示「本区域有机器人巡逻、会识别登记过的工作人员」（给客户一份告示模板）。
- 只做白名单（认保安）。黑名单（认坏人）是 1.2 的事，另外设计。

## 分几步做

| 步 | 内容 | 要真机吗 | 粗估 |
|---|---|---|---|
| 0 | 用现在站点存的人员截图、现场录的包，离线跑 YuNet + SFace：在我们的相机上能认多远、夜里开灯怎样 | 不要（用已有数据）；数据不够再请你批一次现场录 | 2–3 天 |
| 1 | 站点：保安名单、人脸登记（网页 + App 拍照、同意）、特征值加密存、审计 | 不要 | 1 周 |
| 2 | 检测节点：人框里找脸、算特征值、发给站点；站点比对、按上面的判定规矩改「看见人报不报 P1」 | 真机验证（现场 1 天） | 1 周 |
| 3 | 手机靠近：App 发蓝牙、机器人收、站点认人、跟人脸一起判 | 要先定蓝牙硬件；真机 1 天 | 1 周 |
| 4 | 记录、P3「保安经过」、网页 / App 上看每个保安的经过记录 | 不要 | 2–3 天 |

第 0 步的结果决定后面的门槛和「认得出多远」的说法；如果相机在 5 m 认不出脸，人脸就降为辅助、以手机靠近为主。

## 第 0 步结果（11-28，离线，没碰真机）

数据：C40221 现场 10-08、10-13、10-26 站点存的 1835 张人员截图（前相机，1920×1080），YuNet + SFace 在台式机上跑；按时间对上站点记的「几米内有人」。只出数字，没存人脸图。

| 看到的 | 结果 |
|---|---|
| 截图里找得到脸的 | 1284 / 1835（70%），但大多很小：脸宽 10–60 px 的占八成，≥ 80 px 的约 15% |
| 1–3 m 内（按「几米内有人」对上的 239 张） | 有脸的 36%–85%，脸宽中位约 42 px |
| 很近（≤ 1 m） | 只有 36% 拍到脸：相机装得低、往前看，人一走近脸就出了画面上沿（蹲下的人只拍到半张脸） |
| 3–6 m 外 | 脸只有十几到几十个像素，认不了 |
| 相邻两张（多半是同一个人）SFace 比对 | 脸宽 < 40 px 只有 46% 过门槛；40–80 px 64%；≥ 80 px 68%。同一个人都只有三分之二认得出（这个数偏保守：相邻两张不一定是同一个人） |

**结论**：现在的前相机广角、装得低，**能认出脸的只有大约 2–3 m、正对着、站着的那一小段**；保安从旁边走过、背对、离远一点都认不出。所以：

- **手机靠近为主、人脸为辅**（设计里预留的那条路）：认出脸 → 直接记 P3；认不出脸不等于陌生人，有保安手机在附近就走「先问保安」。
- 想让人脸当主力，要**装得高一点、视角窄一点（或能变焦）的相机**，比如上装 V2 的云台相机 —— 算 V2 的事。
- 真机实测（保安在 2、3、4、5 m 正对 / 侧对，白天 / 夜里开聚光灯）放到下一次现场日，要用户批。

## 定下来的（用户 11-28：「按你建议定」）

1. **两种认法都做**：人脸准但近，手机远但粗，一起用才覆盖夜里、背对。
2. **只有手机、脸没认出 → 先问保安（P2 带截图），60 秒没人认 → P1**（上面判定规矩第 3 条）。不按人数放过。
3. **蓝牙**：先查 Orin / 上装板有没有能用的蓝牙（不碰真机，先查资料、问硬件组）；没有就加 USB 接收器。

## 第 4 步：保安经过的记录（11-28 做完，不要真机）

| 项 | 做的 |
|---|---|
| 从哪来 | 机器人发 `face_seen` 事件：`{"faces": [{"feat": [128 个数], "dist_m": 2.4}]}`（第 2 步的检测节点出；现在还没有）。站点在人脸登记里比对 |
| 认出来 | 记进 `guard_passes`（谁、哪台、哪个防区、怎么认的、第一次和最后一次、几次、最高分），出一条 P3「保安 X 经过 B 区」：**只记一笔**（当场算已解决，不响、不推送），报警记录和值班簿里看得到 |
| 并笔 | 同一人、同一台、同一防区，5 分钟内又认出来：并进上一笔（次数 +1），不另出 P3 |
| 认不出 | 这一步**不管**：看见人报不报 P1 还是原来的规矩。按判定规矩改 P1 是第 2 步的事，要上真机 |
| 留多久 | 90 天，到期删；本人撤销人脸同意、管理员删人脸资料时一起删 |
| 谁能看 | 管理员、经理看所有人；别的人只看自己的。看了进审计 |
| 网页 | 授权页「人脸登记」下面「保安经过」：按天看、按人筛，并过的写时间段和 ×n |
| App | 人脸登记页「最近 7 天机器人认出的记录」 |
| 留给第 3 步 | 记录里「怎么认的」已经留了「手机靠近、本人确认」（保安在手机上点「是我」） |
