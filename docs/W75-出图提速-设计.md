# W75 走完一圈 3 分钟出图 设计

来源：
- 用户 2026-11-12：「竞品可以在2-3分钟内把图建好，我们也必须做到」。
- 扫图和测试必须同一天做完，不能提前去扫。
- 用户要的流程：
  1. 在手机上点开始建图，用遥控器带着机器人走，边走边在手机上看预览（不用太精细）。
  2. 走完一圈，在手机上点结束建图。
  3. 后台（机器人和站点）出图越快越好。去噪点可以以后让工程师手点，不用当场跑。
  4. 图建好了发到站点，并通知站点和工程师。
- 要带回环。手机上显示进度百分比。
- 用户 11-12 选了**方案 1：回环放到站点主机上跑**。

旧版（11-04 三步走：按帧重算、预览图、站点重打包）作废，由这一版代替。

## 一、实测：现在慢在哪

用的数据：广场那趟的中间文件（11-04 录包，走 8 分钟、328 m、1071 个关键帧、5900 万个原始点）。在台式机（28 核）上测。

| 步骤 | 现在 | 改完（台式机实测） | 怎么改 |
|---|---|---|---|
| 准备：整个录包重读一遍、取关键帧 | 142 s | 约 0 s | 关键帧边走边存（§3.1），不再重读录包 |
| 回环 | 125 s（整步 138 s） | 约 100 s | 放到站点主机上跑（§3.3）。调参数只省 20%：体素 0.20 m 是 98 s，还找到 46 个回环 |
| 出点云 | 328 s，占 11.8 GB 内存 | 7 s，1.9 GB | 每个关键帧先降采样到 5 cm 再合（sm2mm 5.7 s + mm2ply 1.6 s，得 2630 万点） |
| 降采样（定位地图） | 56 s | 3 s | 体素编号改成一个整数再去重，结果逐点相同 |
| 栅格 | 约 26 s | 约 25 s | 不读录包，用点云模拟射线。噪点以后工程师手点橡皮擦 |
| 去噪 | 1 s | 1 s | 没有录包，射线清除做不了，只去孤点 |

- 机器人上的 Orin 估计比台式机慢 2–3 倍，现在这一套在 Orin 上要二三十分钟。
- 出点云要 11.8 GB 内存，Orin 上放不下。这一步无论如何都得改。

## 二、改完以后的流程

```
开始建图（手机）
  └ 机器人：Super-LIO 边走边建 + 预览（W09f，已有）
            + 新：同一个预览进程边走边存关键帧（降采样到 5 cm），存一个传一个给站点
结束建图（手机）
  └ 机器人：停录；把最后几个关键帧和轨迹、里程、RTK 传完              约 10–30 s
  └ 站点主机：关键帧 → simplemap → 回环 → 点云 → 栅格、定位地图、先验 → 登记成一个版本
                                                                   约 2–2.5 分钟（台式机级别的 x86）
  └ 站点：推送「地图 X 第 N 版建好了」给点开始建图的人和管理员；网页地图页、手机向导都显示出来
```

- 走完到出图的目标：**3 分钟以内**。台式机级别的站点主机估计 2.5 分钟左右。笔记本慢一些，要实测。
- 下发到机器人还是走现有的那条路（W54 向导「用这张图」→ 站点下发）。

## 三、怎么做

### 3.1 边走边存关键帧（机器人）

- 预览进程（`nexwar_localizer.livemap`，Super-LIO 前端时）本来就订着雷达和 Super-LIO 的位姿，这里顺带存关键帧。
- 取关键帧的规则不变：走 0.3 m 或转 10° 取一帧（`superlio.KF_DIST_M` / `KF_TURN_DEG`）。
- 每一帧的处理：
  - 按 0.6–80 m 裁剪；
  - 按 5 cm 降采样，原始点云每帧约 4.5 MB，降采样后小得多（实测总量 2630 万点，约 300 MB）；
  - 写进 `kf/NNNNN.bin`，并在 `index.txt` 追加一行。
- 同时记三样小东西，站点打包时用（原来要从录包里读）：
  - 每一帧的雷达位姿（`traj.tum`）；
  - 机器人自己的里程朝向（核手性用）；
  - 雷达「收到时刻 − 报文头时刻」（配 RTK 时间用）。
- 录包照录。录包是「站点重算不出来时在机器人上从头建」的原料，跟现在一样。
- 存关键帧出了问题（进程没了、盘满）不影响录包。结束建图时发现关键帧不全，就退回现在的老办法：在机器人上从录包打包（§3.5）。

### 3.2 关键帧边走边传（机器人 → 站点）

- 关键帧放进发件箱的新目录 `mapkf/<地图号>/<版本>/`，优先级排在照片、事件后面，排在录包前面。存一个传一个，走完时大部分已经传上去了。
- 预览进程停下时写 `live.json`（里程朝向、时钟差、关键帧小结），边走边写 `lio.tum`（Super-LIO 位姿）。
- 结束建图时再放进去：`rtk.jsonl`（录包里有就带），最后写 `kf.json`（每个文件的大小和 sha256）。
- 站点收齐 `kf.json` 并核对完，才开始打包。这跟地图的 `map.json` 是同一个做法。
- 站点确认之后，机器人上的关键帧就删掉。

### 3.3 站点主机打包（新）

- 站点上新加一个「出图」后台任务，一次只做一张图。它起 `nexwar_loc build --from-keyframes`（新开关），按顺序做：
  1. `kf2sm` → simplemap；
  2. 回环（`mola-sm-lc-cli`，体素 0.20 m，实测 98 s、找到 46 个回环；照旧有把关，挪得离谱就不用）；
  3. 出点云：每帧降采样流水线，见 §3.4；
  4. 定标、核手性（用传上来的里程）；
  5. 栅格：没有录包，用模拟射线；
  6. 定位地图降采样、去孤点；
  7. 先验、覆盖范围、`build.json`。
- 出完直接登记成一个地图版本（来源记机器人 X，备注「站点打包(边走边存的关键帧)」），并推送通知（§3.6）。机器人那边交接时发 `map_handoff`，不发 `map_built`。
- 站点主机要多装一个**出图组件**：
  - ROS 2 Humble 的 MOLA / mp2p_icp 命令行（建图本身是机器人上的 Super-LIO；Super-LIO 没有回环，回环和出点云用 MOLA 的这几个命令行）；
  - 我们自己编的回环工具、`kf2sm`；
  - `install-site.sh --with-mapping` 装，要能上外网（apt）。出图命令装在 `/usr/local/bin/nexwar_site_mapbuild`；`site.json` 的 `mapbuild` 可以改命令或关掉（`{"enabled": false}`）。
  - 没装出图组件的站点，机器人照旧自己打包（§3.5）。
- 打包失败：报 `map_failed` 告警（原因带日志末尾），向导显示失败；关键帧留在站点上。站点重启后不自动重跑失败的；收齐了没出的接着出。
- 一次只出一张；只收站点让这台机器人建的那一版；路径、清单对不上的不收。

### 3.4 出点云、降采样改快（机器人、站点都用）

- 出点云：sm2mm 换一条「每个关键帧先 5 cm 降采样」的流水线，再 mm2ply。实测时间从 328 s 降到 7 s，内存从 11.8 GB 降到 1.9 GB。
- 定位地图降采样（`slioloc.voxel_down`）：体素编号压成一个 int64 再去重，从 56 s 降到 3 s，结果逐点相同。
- 这两项跟在哪打包没关系，**先做**。机器人自己打包时 Orin 也不会再爆内存。

### 3.5 退回：在机器人上打包

以下几种情况，照现在的办法在机器人上打包：站点没装出图组件；关键帧不全（预览进程没正常收尾，没有 `live.json`）。这条路也用 §3.4 的快办法，但不在 3 分钟的目标里。

在哪打包由**站点**定：站点装了出图组件，「开始建图」命令就带 `pack: site`；没装就不带，机器人自己打包。老机器人不认这个字段，照旧自己打包。（原来设想的机器人配置 `NEXWAR_MAP_PACK_AT` 不做了。）

还没做：站点出图失败后，向导里「在站点上重试」「在机器人上重建」两个按钮。现在只能重走一圈。

### 3.6 进度和通知

- **进度百分比**按阶段给，每段占多少按台式机实测时间的比例：
  - 机器人：「上传关键帧 已传 a/b」；
  - 站点：「回环」「点云」「栅格」「定位地图」，各自报百分比。
- 手机向导：站点出图时把转圈换成进度条，加一行阶段名和百分比。（网页没有建图向导，不改。）
- **建好了**：站点记一条 P3「地图已建成：X:N」（`map_ready`），推送给管理员和工程师；之前的建图失败告警自动解决。
- **没建成**：报 `map_failed`「站点出图失败」，也推送给管理员和工程师。
- 现在只有站点出图这条路会推「建好了」；机器人自己打包的照旧不推。

| 步 | 内容 | 好处 |

| 一 | §3.4 出点云和降采样改快 | 机器人上打包不爆内存，从二三十分钟降到几分钟；跟后面几步无关 |

- 每一步做完都在开发机上用广场的数据测一遍时间。
- 第二步到第四步要上一台真机（Orin），从开始建图走到推送，完整走一遍再算完成。

### 3.7 POC 的站点主机：现场笔记本

用户 11-12 定：POC 的站点主机就是现场笔记本。笔记本上的站点从仓库直接跑，没走 `install-site.sh`。要做四件事：

1. 装 ROS 2 Humble 里回环、出点云用的 MOLA 命令行（Super-LIO 不用装到笔记本上；要外网，约 2 GB）：
   `sudo apt-get install -y ros-humble-mola-sm-loop-closure ros-humble-mp2p-icp ros-humble-mola-metric-maps ros-humble-mola-lidar-odometry ros-humble-mrpt2 python3-numpy cmake g++`
   （没有 ROS 2 的 apt 源，先按 `install-site.sh` 里 `--with-mapping` 那段加。）
2. 编 kf2sm，放到 `~/.cache/nexwar-superlio/bin/kf2sm`：在 `packages/localizer/native/superlio/kf2sm` 上跑 `cmake -DCMAKE_PREFIX_PATH=/opt/ros/humble` + `make`。
3. `site.json` 里加：
   `"mapbuild": {"runner": ["env", "NEXWAR_SUPERLIO_ROOT=<家目录>/.cache/nexwar-superlio", "<仓库>/deploy/site/nexwar_site_mapbuild"]}`
   重启站点后，日志里没有「没装出图组件」这一行就是启用了。
4. 先在笔记本上用广场或 speed06 的关键帧量一次出图时间、看内存。

风险：
- 回环那一步在广场那趟上最多占 8–12 GB 内存，笔记本内存要 16 GB 以上，出图时别同时跑别的大程序。
- 笔记本比台式机慢，3 分钟能不能做到要实测。
