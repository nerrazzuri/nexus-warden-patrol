# POC Top Glove（11-17）：跟竞品一起录包 —— 周一演练单

**背景**（用户 11-13）：11-17 竞品用 C40221（装着竞品上装 + Oneway 平台）给客户演示建图，用户遥控机器人。我们在 Orin 上同时**只录包**，回来自己建图，和竞品导出的图对比。

竞品上装自己没有激光雷达，用的是机器人的前后雷达和雷达 IMU（Orin 上 `~/bridge_start.sh` 转给竞品的 ROS1）。所以我们录的就是竞品建图的原始输入。**bridge 开着，我们不碰它。**

演练时间：周一 11-16（笔记本最早这天才能连上机器人）。只做录包，不让机器人动之外的事；起立、趴下、第一次动照旧先问用户。

## 0. 准备（笔记本）

- Orin 上的代理是 POC 分支最新版（带「跟竞品一起录」，提交 56d0888a 或之后）。
- App 是 POC 版最新 APK。
- 记下 Orin 剩余空间：`df -h /var/lib/nexwar`（或代理的发件箱所在盘）。

## 1. 竞品不跑时，先单独录 3 分钟

1. App → 机器人 A → 录包：**地图号、版本都留空**（只录包），开录。
2. 录包轨迹页应显示「按机器人剩余空间，大约还能录 N 分钟」。记下 N。
3. 推着或遥控走 3 分钟，停录。
4. 轨迹页应显示「上一个包 …：录了 3.x 分钟，x.x GB」「每个话题都录到了数据」。
5. 算实际速率：GB ÷ 分钟，记下来（代码里按 40 MB/s ≈ 2.4 GB/分钟估，实测差太多就告诉台式机改）。

**通过**：小结里没有「一条都没录到」，索引在；实际速率记下了。

## 2. 竞品 bridge 开着、竞品建图跑着，再录 5 分钟

1. 确认 bridge 在跑（竞品 App 能看到雷达）。
2. 开录（同上，只录包）。
3. 录包期间在 Orin 上看 CPU：`top -b -n 3 -d 2 | head -40`，记下：
   - `ros2`/`bag` 进程的 NI 列是 **10**（降了优先级）；
   - bridge（ros1_bridge）占多少 CPU；整机空闲多少。
4. 竞品那边：建图画面有没有卡顿、掉帧（问竞品的人，或看他们的 App）。
5. 停录，看小结。

**通过**：我们的录包进程 NI=10；竞品建图不受影响；小结每个话题都有数据。

**不通过就停**：竞品画面明显卡、雷达断，立刻在 App 停录，记下时间和 top 输出，发给台式机。

## 3. 竞品主控只读查找（周一先找位置）

见台式机发的「竞品只读查找清单」：只看、只复制，不改、不删、不重启。找到地图文件（pcd、pgm、yaml）、轨迹、参数分别放在哪个目录，记下来。

## 4. 把包拉回笔记本

- 包在 Orin 发件箱 `bags/` 下，目录名是开录名加时间。
- 拉到 `runs/topglove-1116-rehearsal/ours/`，附 `sha256sum`。
- 不要在 Orin 上删包（站点确认收到后代理自己删；盘紧时也是传完的才删）。

## 5. 报告给台式机

- 第 1、2 步的分钟数、GB、实际 MB/s、剩余能录几分钟；
- 第 2 步 top 的那几行；
- 竞品文件位置；
- 有异常的话：时间、现象、日志（代理日志、`runs/logs/bagrecord.log`）。

## 11-17 当天（演练通过后照做）

1. 竞品开始建图前开录（只录包）。
2. 盯着轨迹页的「大约还能录 N 分钟」：剩 10 分钟以内就先停录、再开一个新包，或者跟用户说。
3. 竞品结束建图后停录，看小结。
4. 竞品导出后，按查找清单把他们的 pcd/pgm/yaml、轨迹、参数复制回笔记本 `runs/topglove-1117/competitor/`。
5. 我们的包拉回 `runs/topglove-1117/ours/`。
