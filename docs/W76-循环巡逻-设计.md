# W76 循环巡逻 设计

来源：用户 2026-11-12：「普通巡逻任务需要加循环次数，可以选无限次数，一直到电量低于我们设置的值，就停止巡逻任务并回去充电/换电池，如果没循环那怎么叫巡逻呢？」

用户同天定：
- 补能以后**这趟任务就结束**，不自动接着跑。
- 回去补能的电量线**全站统一设一个**。
- **11-17 POC 前做完**。
- 一直巡逻**马上派、不看日程；日程到点就停下它、改跑日程**，跑完不再接着一直巡逻（做法见 2.3）。
- **换电池是值守保安的活**：换电提醒只推给保安；**超过半小时**没人换才升级推给经理（原来 20 分钟、推给所有人）。

用户问「圈数为 0 怎么跟设了圈数跑完分开」：0 只是机器人和站点之间的代号，界面上只有「一直巡逻」。结束时详情里写 `ended`：设了几圈跑完 = `loops`（完成）；一直巡逻电量到线 = `battery`（完成）；设了几圈半路电量返航 = `battery`（失败）。都带 `laps`（跑了几圈）。

## 一、现状（核过代码）

- 契约里本来就有圈数 `policy.loops`（正整数，默认 1）。机器人引擎按圈数一圈圈跑（`engine/machine.py`）。
- 跑的路上电量到返航线，机器人会停下这一趟、回原点（`safety.battery_ruling` → `_go_home`）。返航线 = `max(policy.battery_return_pct, 停止线 + 回原点耗电 × 1.5)`。
- 半路返航回到原点后，代理报这一趟**失败**（「…半路返航，已回到原点」），因为点没跑完。
- 网页、手机派巡逻**都没有地方选圈数**，也没有「无限」。
- 回去以后：
  - 有桩：站点自动回充，电量 ≤ 30% 时机器人空着就起。
  - 没桩：换电引导（`battery_swap.py`）现在只由布防值守的「不够跑一圈」触发，普通巡逻低电回去不会叫人换电池。
- 布防值守（W73）本来就能一圈圈跑，有自己的电量规则，这一单不动它。

## 二、怎么做

### 2.1 契约：`loops = 0` 表示无限

- `policy.loops` 允许 0，意思是「一直跑，直到电量到线」。1–99 照旧是圈数。
- 老机器人的代理不认 0（会按「应为正整数」拒收）。机器人能力里加 `tasks.patrol.loops_forever: true`，站点只给报了这一项的机器人派无限圈，没报的回 409「这台机器人的程序太老，不支持无限循环，请先升级」。

### 2.2 机器人

- 引擎：`loops == 0` 就一圈接一圈跑，直到电量到返航线，然后回原点（走现有的返航）。
- **无限圈因为电量到线回到原点 = 这一趟正常结束**：报完成（`done`），详情写跑了几圈、「电量到线，已回原点补能」。有限圈半路返航照旧报失败。
- 防空转：无限圈里**一整圈一个点都没到**，就中止这一趟（报失败：「一整圈一个点都没到」），不再空转到没电。
- 发布状态时带上「第几圈」，站点、手机显示「第 3 圈」。

### 2.3 站点

- **全站电量线**：值班设置里加 `patrol_return_pct`（默认 25%，可设 20–60%）。手动派的巡逻都把它写进 `policy.battery_return_pct`。机器人自己还会按回原点的路程算，取两者里高的，所以设低了也不会回不去。
- **派巡逻**接口（`POST /api/robots/<id>/patrol`）加 `loops`：1–99，或 0 = 无限。不给就是 1，跟现在一样。
- **估时**（临时巡逻要避开日程）：有限圈按一圈 × 圈数；无限圈按「从现在的电量用到电量线」算。
- **日程到点打断一直巡逻**（用户定）：一直巡逻按优先级 5 派（排程 10–49，回待命点 -10），任务号前缀 `adhoc-forever-`。排程挑机器人时把正在一直巡逻的那台当成能派（有空着的先用空着的），机器人收到更高优先级的日程自己停下一直巡逻（`task_preempted`）。派之前「先看会怎样」写出会被哪一趟日程打断（`interrupted_by`）。
- **回去以后**（`patrol_energy.py`）：
  - 有桩：回充的起充线 = 全站电量线（跟值守的线取高；默认 25% 跟原来一样）。
  - 没桩：**上一趟是因为电量到线结束的**（终态详情 `ended: battery`）、机器人空着、电量在线下 → 起换电引导。只看电量不行：换电引导会叫停在动的机器人，低电时有人遥控会被打断。
  - 换电提醒（`swap_needed`）只推保安；30 分钟没进展的升级（`swap_overdue`）只推经理。
- 机器人卡片（网页总览、手机机器人视图的 `lap`）显示「第 n / m 圈」或「一直巡逻 · 第 n 圈」：按这一趟报了几个点 ÷ 每圈几个点算。

### 2.4 网页、手机

- 派巡逻的地方加「循环次数」：1、2、3、5、10、一直巡逻（到电量线回去补能）。默认 1。
  - 网页：路线页「派一趟」（`routedispatch.tsx`）、机器人页「开始巡逻」（`robotspage.tsx`），共用 `loops.tsx`。
  - 手机：派巡逻底部弹框（`patrol_dispatch.dart`，机器人页、值守页共用）。路线页里的「派一趟」这一期不加，照旧一圈。
- 网页「布防时间」页的值班设置加「巡逻回去补能的电量（%）」。

### 2.5 不做

- 补能后自动接着跑（用户定：这趟结束）。
- 排程里的圈数：排程已经有「每隔 N 分钟一轮」。要的话以后再加。
- **路线库、任务包里不许存「一直巡逻」**（`loops` 0 存路线、导入都拒）：一直巡逻只在派的时候选。存进路线的话，日程会把它派出去，既不查机器人支不支持，也不走「比日程低的优先级」。
- 布防值守不动。

## 三、测试

- 契约：`loops` 0 能解析、能写回；负数、布尔照旧拒。
- 引擎：无限圈跑到电量到线 → 回原点、报完成、带圈数；一整圈一个点都没到 → 中止；有限圈半路返航照旧报失败。
- 站点：
  - 派巡逻带 `loops`：写进任务；老机器人派无限圈回 409；
  - 电量线写进 `battery_return_pct`；
  - 估时；
  - 起充线跟着电量线走；
  - 没桩时巡逻低电结束起换电引导。
- 网页、手机：选循环次数发出去的请求对；值班设置能改电量线；文案中英文都有。
- 真机：C40221 上跑无限圈，把电量线临时设高（比如比当前电量低 2%），看到线回原点、报完成、站点起回充或换电。

## 四、外审第 1 轮（2026-11-12）怎么改的

报告 `reviews/W76-外审-1.md`：FIX-THEN-APPROVE，Important 10 条、Minor 1 条。

| # | 问题 | 改法 |
|---|---|---|
| 1 | 一直巡逻低电返航途中被日程抢掉，停在半路 | 返航途中代理报有效优先级 50（高过排程 10–49，低过手动 60）；日程拿到「忙」，等它到家 |
| 2 | 路线写了「低电接着走」再选一直巡逻，会跑到中止线停在外面 | 契约拒收这一组合；站点派一直巡逻时换成回原点 |
| 3 | 按动态返航线提前回来，电量高过全站线，不补能 | 补能不跟全站线比：最近一趟巡逻因电量结束、2 小时内、空着、电量没到 80%（换好线）就补 |
| 4 | 回待命点盖掉「因电量结束」；直线的报回待命点失败 | 一直巡逻结束不自动回待命点；补能只看巡逻那一趟 |
| 5 | 换到一半站点重启，换电流程丢了 | 同 3：两块合起来不到 80% 照样接上 |
| 6 | 一直巡逻的历史把单圈估时拉到几小时 | 估时历史只认一圈的 |
| 7 | 界面选 1 圈，路线里存的多圈照跑 | 网页、手机总是发选的圈数 |
| 8 | 新手机配老站点，选了圈数被静默忽略 | 「先看会怎样」回 `loops`，手机有它才给选 |
| 9 | 一直巡逻结果无限增长 | 一直巡逻至少两个点（一个点会原地空转）；其余受电量限制（一趟最多三四小时），不再截短 |
| 10 | 没有保安手机时换电提醒谁都收不到 | 没有保安的手机改推经理、管理员；没有经理的手机，升级推管理员 |
| 11 (Minor) | 第几圈的查询随历史变慢 | 先不改 |
