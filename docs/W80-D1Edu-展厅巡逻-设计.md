# W80 D1 Edu 展厅巡逻（设计稿）

用户 2026-11-24：「我有个紧急需求，需要我开发一个 D1 Edu 的简单巡逻场景……我用的是 Wheeltec N10P 的 2D 激光雷达，加上一个深度相机……主要场景就是在展厅上部署一个简单的导航，巡逻，避障能力」。同一天定的：

- 背上加一块 **RK3588** 板子跑我们的东西；
- **接进我们的站点和 App**（不是另起一套）；
- **两周左右**在展厅跑起来；
- 深度相机型号还没定（本稿 §2 给推荐）。

厂家资料在用户 OneDrive「AgiBot D1 Edu SDK Development Guide」：SDK v0.2.7（ZSL-1 = D1 Edu 点足）、说明书、URDF。台式机拷了一份在 `../d1edu-vendor/`（不含 77 MB 的 STEP 模型）。

## 1. D1 Edu 跟 D1 Max 不一样的地方（看资料得出的，要真机核）

| 项 | D1 Edu（ZSL-1） | D1 Max（我们现在的） | 对我们的影响 |
|---|---|---|---|
| 机身电脑 | 8 核、6 TOPS，**厂家说没有余量，不建议放程序**（SDK 指南 Q20） | 厂家 Orin，我们的东西在上面跑 | 全部放背上的 RK3588 |
| 雷达 | 没有 | 前后两台 RS-Airy 3D | 用 N10P 2D 雷达；**定位、建图换成 2D**（§3.2、§3.3） |
| 相机 | 头部一个前摄，`rtsp://192.168.234.1:8554/test` | 前后摄 | 画面照我们现在的推流接 |
| SDK | `move(vx, vy, yaw_rate)` 直接收 m/s、rad/s；vx 0.05–3、vy 0.1–1.0、yaw 0.02–3.0，**不动时发 0** | `Move` 收比例值，有档位、死区 0.2 m/s | 换算简单得多，死区小 |
| 断联保护 | **3 秒收不到 SDK 数据 → 阻尼、趴下**（Q9） | 类似 | 旁路要一直发（20–50 Hz）；板子死机 = 机器人自己趴下 |
| 遥控器 | **SDK 优先级比遥控器高，不能同时用**（Q11） | 遥控器能抢回控制 | **手持遥控器在我们控制时抢不回来**，见 §5 |
| 里程 | `getPosition()` 上电原点系位置、`getWorldVelocity()`、`getBodyVelocity()`，50 Hz | 旁路报里程 | 腿式里程，漂移多少要真机量；2D 扫描匹配兜底 |
| 网络 | Wi-Fi 热点 192.168.234.1；网口 192.168.168.168（无 DHCP）；SDK 目标 IP 写在 `/opt/export/config/sdk_config.yaml`，**厂家升级会被重置**（Q17） | 类似 | 装机脚本、开机自检要核这个文件 |
| 背上供电 | 12 V、24 V 各一路，**合计 ≤ 36 W**；M4 安装孔 | — | RK3588 + 雷达 + 深度相机要在 36 W 内（§2） |
| 尺寸 | 站立 635 × 360 × 420 mm，15.5 kg，额定负载 5 kg | 大得多 | Nav2 外形、窄处判断要换 |
| ROS | 厂家**没有 ROS 接口**（Q18） | 我们自己写的旁路 | 旁路照样自己写 |

## 2. 硬件

- **RK3588 板**：Ubuntu 22.04 + ROS 2 Humble。上装结构那边已经把我们的 build 34 装上过（板 1），这次最好用**一块单独的板**（板 2 备用那块？用户定）。网线接机器人网口（192.168.168.x 段，SDK 走有线最稳），Wi-Fi 连现场或站点。
- **N10P 2D 雷达**：USB 串口。装在背上最高处，**360° 不被头和机身挡**；离地高度记下来（大约 0.45–0.5 m），比它低的东西 2D 雷达看不到，靠深度相机。驱动用 Wheeltec / 镭神给的 ROS 2 驱动（源码编），出 `/scan`。
- **深度相机（推荐）**：**奥比中光 Gemini 336 / 335 系列**优先 —— 官方 OrbbecSDK v2 支持 ARM64、有 ROS 2 驱动，USB 3 一根线供电和数据；备选 **RealSense D435i**（ROS 2 驱动最成熟，ARM 上要用 RSUSB 后端）。装在头部下方、朝前**往下斜 20–30°**，看得到机头前 0.3–2 m 的地面和低矮东西（展台底座、台阶、箱子）。
- **功耗估算**：RK3588 满载约 10–15 W，N10P 约 2 W，深度相机约 2–4 W，合计约 20 W，在 36 W 内。要接显示器、键盘调试的时候外接电源。
- **急停**：见 §5。

## 3. 软件：哪些复用、哪些要新写

**原则**：站点、App、网页、巡逻引擎、路线、区域、告警、发件箱、升级、开通全部照用；D1 Edu 在系统里就是「另一种型号的机器人」。新写的只有贴着机器人和传感器的那一层。

### 3.1 运动：D1 Edu 旁路（新写，小）

- 新的旁路进程 `nexwar_sidecar_edu`（Python，用厂家的 `mc_sdk_zsl_1_py`，aarch64、cpython 3.10 —— Ubuntu 22.04 自带的就是 3.10），**说跟 D1 Max 旁路一样的 TCP 行协议**（`patrol_agent.cpp` 那套：`walk`、`halt`、`estop`、`stand`、`lie`、状态与里程帧）。这样代理那边直接用现有的 `D1MaxHal`，只换配置：`mps_per_unit = 1`、`radps_per_unit = 1`、`fwd_offset = 0`、`deadband_mps = 0.05`、横移按 SDK 的 0.1–1.0 m/s 开，没有档位。
- 旁路自己做的：**一直以 50 Hz 发 `move`**（没有速度命令就发 0，3 秒不发厂家就趴下）；速度命令有效期过了自动归 0；连 SDK 失败、`checkConnect` 掉了就报给代理；站起、趴下走厂家的状态机（不按顺序会摔，SDK 文档「运动控制状态机」）。
- 里程：`getPosition()` + `getQuaternion()` → 里程帧（机身系），`getBodyVelocity()` → 速度，同时发 ROS 的 `/odom` 和 `odom → base_link`。电量 `getBatteryPower()`，模式 `getCurrentCtrlmode()`。
- 型号：契约里加一个机器人型号 `d1edu`，能力表照实报（没有 3D 雷达、没有尾为前、没有上装、没有回充），站点和 App 按能力藏掉用不上的按钮。

### 3.2 建图：2D，在板子上实时建

- 用 **slam_toolbox**（`online_async`），输入 N10P 的 `/scan` + 旁路的 `/odom`。2D 在 RK3588 上很轻，**边走边出图**，手机建图向导里能实时看。
- 走法跟现在一样：App 建图向导「开始建图」→ 人遥控走一圈 → 「结束」→ 板子把图存成我们现有的地图版本格式（`floor.pgm`、`floor.yaml`、`coverage.json`、`build.json`，再加 slam_toolbox 的 `.posegraph`、`.data` 当这版的定位先验）→ 经发件箱传站点、站点登记、发布、下发。2D 图一版只有几 MB，4G 上也几秒传完。
- 我们 W09c1 之前用过 slam_toolbox 这条路（`74899ef3` 退役的），代码可以翻出来参考。
- **展厅玻璃**：2D 雷达会透过玻璃，图上漏出去的假空地照现在的办法在网页上「抹掉」、画虚拟墙。

### 3.3 定位：AMCL（新的定位后端）

- 定位器加一个后端 `--engine amcl2d`：跑 Nav2 的 **AMCL**，用这版的 `floor.pgm` + `/scan`；位姿、可信度按现有的 locbridge 报给代理，代理、站点、App 都不用改。
- 「设位置」= 给 AMCL 发初始位姿；「自动找位置」= AMCL 全局定位（撒满粒子）+ 我们现有的「稳下来再复核」（扫描跟图对得上才算数，§E06 那套）。
- 可信度：AMCL 的协方差 + 扫描跟图的贴合度，掉下去时照现在的规矩减速、停、报。

### 3.4 避障：2D 雷达 + 深度相机

- **Nav2 代价地图**：障碍层吃 `/scan`；体素层吃深度相机点云（滤掉地面、只留 0.05 m 到机身高度的点）。
- **我们的守卫**（`nexwar_obstacles` → 代理守卫）：输入从「3D 雷达点云」改成可配：2D 扫描当成雷达高度上的一圈点 + 深度相机点云。停障、减速、两侧盲带的规则照用；D1 Edu 身子小、前后都有雷达覆盖（2D 是 360°），盲带比 D1 Max 窄。
- Nav2 参数单独一份 `deploy/nav2/params_d1edu.yaml`：外形 0.64 × 0.36 m、最快 0.6 m/s 起步（展厅人多，先慢）、MPPI，RPP 当备用。

### 3.5 画面

头部前摄的 RTSP 接到我们现有的推流（`video_push`），站点、App、网页的 Live 页照用。深度相机的彩色画面可以当第二路（后做）。

### 3.6 这两周不做

人员检测（RK3588 的 NPU 要另移植模型，下一步再做）、警灯警笛喇叭、回充、3D 地图、RTK、多楼层。

## 4. 两周排期（10 个工作日）

| 天 | 做什么 | 要什么 |
|---|---|---|
| 1–2 | 台式机：旁路（先用 x86 版 SDK 经 Wi-Fi 连真机测站起、走、里程）；契约、站点、App 加 `d1edu` 型号；Nav2 参数；定位器 `amcl2d` 后端；守卫吃 2D + 深度 | 机器人能连上台式机（Wi-Fi 就行） |
| 3–4 | RK3588 装系统和驱动（N10P、深度相机）、装我们的包；真机：站起趴下、遥控、里程漂移、急停 | 板子、雷达、相机、支架到位 |
| 5–6 | 建图 → 站点登记 → 下发；设位置、自动找位置 | 一块场地（办公室就行） |
| 7–8 | 展厅现场：建图、画禁行区、巡逻路线；导航避障调参 | 展厅 |
| 9–10 | 整套演练、出一张勾勾表、修 | 展厅 |

台式机这边第 1–2 天的活不等硬件就能开始；**深度相机型号定得越早越好**（驱动和安装角度要按型号来）。

## 5. 安全（要用户定）

- **手持遥控器抢不回来**：厂家说 SDK 在控制时遥控器不管用。我们这边能停的是：App / 网页的「停」、急停按钮（站点叫停 → 旁路发 0 → 原地站住）；板子断电或死机 → 3 秒后厂家自己趴下。
- **建议**：加一个**物理急停**（背上一个蘑菇头按钮，接 RK3588 的 GPIO，按下旁路马上发 0 并趴下；或者直接断开 SDK 让厂家 3 秒后趴下）。成本几十块，展厅有观众时很有用。
- 建图、调参时人遥控，用的是我们 App 的遥控（不是厂家遥控器）。
- `SDK_CLIENT_IP` 配错会让厂家遥控器失灵、机器人原地「俯卧撑」（FAQ Q14）：装机脚本配好以后开机自检核一遍。

## 6. 要用户定 / 给的

1. 深度相机：按 §2 推荐买奥比中光 Gemini 336/335（首选）还是 RealSense D435i？
2. RK3588：用哪块板子（上装结构那边的板 2？还是另买一块）？
3. 雷达、相机的支架：谁做、什么时候到？装好后量一下雷达离地高度、相机朝向。
4. 物理急停要不要加（§5）？
5. 机器人什么时候能到台式机这边（先用 Wi-Fi 连台式机测旁路）？
6. 展厅：多大、有没有大片玻璃、开放时间（调参要清场）、什么时候能进。

## 7. 风险

- **腿式里程**的漂移多大不知道；漂得大 slam_toolbox / AMCL 也能兜，但建图要走慢、多回环。第 3 天量。
- **2D 雷达看不到的东西**（低于约 0.45 m 的展台底座、台阶、悬空的桌面）只靠深度相机，深度相机只看前方 —— 倒车、原地转身时身后、两侧低矮的东西看不到。巡逻时少倒车，展台周边画禁行区。
- **展厅人多**：2D 定位在人多时会被挡，AMCL 一般扛得住；人特别多的时段先别跑。
- **厂家升级**会重置 SDK 配置：升级以后要重跑我们的装机脚本。
