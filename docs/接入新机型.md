# 接入新机型（W80 解耦，2026-11-25）

用户 11-25：「加 D1 Ultra、D1 Max Pro，甚至宇树、云深处的机器狗，应该只要最小改动的适配就可以了。」

## 一句话

**机型相关的东西全写在一份机型档案里**（`/etc/nexwar/robot-models/<编号>.json`），代理按 `--robot-model <编号>` 读。站点、App、网页都**不认机型**，只看机器人上报的能力（相机有几路、有没有灯、能不能横移、有哪些服务），所以新机型不用改站点、App、网页。

| 新机型 | 要做的 | 主仓库改代码吗 |
|---|---|---|
| 同一家、同一套 SDK（D1 Ultra、D1 Max Pro……） | 放一份档案；真机标一下换算系数 | 不改 |
| 说我们旁路协议的任何机器人（D1 Edu 就是这样接的） | 写一个旁路进程 + 一份档案，放在自己的品牌包里 | 不改 |
| 不走旁路协议的（想直接在代理里接厂家 SDK） | 品牌包里写一个 HAL，档案 `driver` 写 `模块:函数` | 不改 |

## 机型档案

内置的只有 D1 Max（`nexwar_agent/robot_models.py` 的 `D1MAX`）。别的机型的档案跟着它的品牌包走，由品牌包的装机脚本放进 `/etc/nexwar/robot-models/`。D1 Edu 的档案在 `nexwar-d1edu/deploy/robot-models/d1edu.json`，可以照抄。

```json
{
  "schema": 1,
  "id": "d1edu",                      // 小写字母开头,文件名要跟它一样(d1edu.json)
  "name": "D1 Edu",                   // 给人看的
  "adapter_id": "nexwar-d1edu/0.1.0", // 报给站点的适配器号;不写用驱动自己的
  "driver": "sidecar",                // "sidecar" = 旁路协议;或者 "品牌包模块:函数"
  "cameras": ["front"],               // 自带哪几路:front / back / thermal / payload
  "light": false,                     // 有没有机身灯
  "units": {"mps_per_unit": 1.0, "radps_per_unit": 1.5, "deadband": 0.05,
            "lateral_mps_per_unit": 1.0},
  "unit_ranges": {"mps_per_unit": [0.7, 1.5]},  // 可不写:缺省用 D1 系列 SDK 低速档的范围
  "robot_radius_m": 0.35,             // 可不写:缺省用引擎的
  "mapping_orchestrator": "nexwar_d1edu.slam2d:orchestrator",  // 可不写:用 D1 Max 的 3D 建图
  "services": ["nexwar_d1edu_sidecar", "nexwar_d1edu_lidar", "nexwar_nav2"]
}
```

（JSON 里不能写注释，上面的注释只是说明。）

- 档案写错了（不认得的键、相机名不对、换算系数不在自己的范围里、文件名跟 `id` 不一样、跟内置的编号重了），**代理不起，并说清楚是哪一项**。
- 命令行给了的参数（`--deadband`、`--robot-radius`、`--mapping-orchestrator` 等）以命令行为准；没给的取档案里的值，档案里也没有的用缺省值。
- `services`：这个机型在机器人上跑的我们的服务。站点上能看状态、看日志、重启这些服务。`nexwar_agent`、`nexwar_bind` 每个机型都有，不用写。
  - 远程重启要 root，要由执行器来做。执行器只认 `/etc/nexwar_ops.json` 里的 `extra_units`（只认 `nexwar_` 开头的名字），这一项由品牌包的装机脚本写进去，D1 Edu 的装机脚本可以照抄。
- 上装（警灯、警笛、喇叭、探照灯）**不在档案里**，在 `payload.json` 里（W79：机器人单卖、带上装卖、以后加上装）。

## 三条路

### 1. 同一套 SDK 的新型号（D1 Ultra、D1 Max Pro）

1. 写 `<编号>.json`：相机、灯、半径、`adapter_id`；`services` 照 D1 Max 的写（`robot_models.D1MAX.services`），少什么删什么。
2. 装机：主仓库装好以后，把档案拷进 `/etc/nexwar/robot-models/`，`/etc/nexwar/env` 的 `NEXWAR_AGENT_ARGS` 加 `--robot-model <编号>`。
3. 真机标定换算系数（跟 D1 Max 一样：`deploy/nexwar_units_check`、`docs/真机验证.md`）。实测值写回档案的 `units`。如果新型号 SDK 的速度档不一样，`unit_ranges` 也写上。

### 2. 别家机器人，写一个旁路进程（推荐）

照 `nexwar-d1edu` 做：

- **旁路进程**（`nexwar_d1edu/sidecar.py`）：
  - 协议处理（认证、排队、插队的停车急停、净空许可、回执）**整个复用** `nexwar_sim.agent_server.SimAgentServer`，它是旁路协议的可执行契约，也是 `motion/patrol_agent.cpp` 那一套协议；
  - 品牌包只写「机身」那一层（`nexwar_d1edu/robot.py`）：速度怎么下发、站起趴下、读状态 / 里程 / IMU、急停、SDK 掉线。
- **定位、避障**：
  - 定位走 `nexwar_contract.locbridge` 那套桥协议；
  - 避障走障碍栅格桥；
  - 导航用主仓库的 Nav2（`nexwar_nav2`），参数按机身外形生成（`nexwar_d1edu/nav2params.py`）。
- **建图**：用 D1 Max 的 3D 建图，或者在档案里写 `mapping_orchestrator`（D1 Edu 是 2D 的 slam_toolbox）。
- **相机**：
  - 自带的几路按 `rtsp://<相机主机>:8554/<路名>` 拉；
  - 地址不一样的写在 `/etc/nexwar/cameras.json` 里；
  - 档案的 `cameras` 只写真有的几路。
- **装机脚本**（`deploy/install-d1edu.sh`）：
  - 装档案、服务单元；
  - 把 `extra_units` 写进 `/etc/nexwar_ops.json`；
  - `NEXWAR_AGENT_ARGS` 加 `--robot-model`；
  - 停掉 D1 Max 那几个用不上的服务。

代理那头还是 `--hal d1max`：`d1max` 是历史名字，意思是「真机器人，走旁路协议」。

### 3. 别家机器人，在代理里直接接 SDK

档案写 `"driver": "品牌包.模块:函数"`。代理调 `函数(model=档案, args=命令行参数, now_ms=取毫秒时钟, payload=上装)`，拿回一个实现 `nexwar_contract.hal` 接口的 HAL。

这时旁路协议的换算系数范围不检查，换算由驱动自己负责。

这条路不推荐：

- 厂家 SDK 跟代理跑在一个进程里，SDK 崩了会把代理一起带走；
- 拿不到旁路进程那一层保护（命令有效期、插队急停、净空许可）。

只有厂家 SDK 只能在本进程里调用时才走这条。

## 不用动的

- **站点**：机型只是证书里的一个说明字段，站点不按它分支。
- **App / 网页**：相机几路、灯、喇叭、横移、遥控限速，全按机器人上报的能力显示。
  - 没有后摄像头的机器人，告警录像里不给「换后摄像头」按钮（W80）。
  - 「去某点拍一张」只会让机器人用它报了的相机拍（W17）。

## 还没通用的（以后碰到再拆）

- 竞品上装（`anbot_ros1`）的适配写在 `nexwar_adapter_d1max.anbot` 里，只配旁路协议的机器人。
- 驱离用的机身灯按「前 / 后」两侧算。灯不是两侧的机型，`light` 先写 `false`。
- **巡逻路线里的拍照不看机器人有没有那一路**：路线不分机器人，站点照原样下发。路线里某个点勾了「拍后面」，派给没有后摄像头的机器人（D1 Edu），这个点会报「没有配 back 这路相机的取流」，按失败处理。要改：代理遇到自己没有的相机，跳过并记一笔；或者站点下发时按机器人报的相机去掉。这属于巡逻行为的改动，待用户定（11-25）。
- 主仓库的装机脚本（`install-robot.sh`）装的是 D1 Max 全套。别的机型由品牌包的装机脚本停掉用不上的服务（D1 Edu 就是这样做的）。
