# 外网站点方案（POC 用）

2026-11-20 晚，用户经笔记本提出：站点放外网，以后所有 POC 都用它。机器人开机上网后自己连回站点；人在哪都能看、能派任务，也能远程 SSH 进 Orin。另外买一台 N100 放办公室，做远程基础测试、自动拉日志。

本文只出方案，不改代码。

> **状态（2026-11-21 用户）：先不搞公网，方案留着，以后再做。** 机器选型当时比过的：
> - Hostinger KVM 2（吉隆坡），预付 24 个月约 US$9/月；按月付 US$24–26 起，还会涨。
> - Contabo Cloud VPS 4（新加坡），约 US$8–10/月，CPU 超卖。
> - Vultr 新加坡，约 US$24/月。
> - 免费的：Oracle Always Free 2026 年额度被砍、闲置会被回收，不适合 POC；办公室 N100 自己当站点，要办公室宽带有公网 IP。
>
> 重启这件事时，先查 N100 所在宽带有没有公网 IP；没有就上 Contabo。

## 结论先说

1. **26 号带笔记本做现场站点。** 外网站点赶在 26 号前也能搭起来，但 26 号要建图：一张图的关键帧约 350 MB，走客户网络上传，比笔记本在局域网里慢得多。建图当天出问题，也没有退路。
2. **外网站点以 12-02 POC 为目标。** 26 号建完图回来，在办公室用 N100 和一台机器人先演练一轮，再上 POC。
3. **第一期只开 WireGuard 一个端口。** 这一期不用改代码，全部用已有的东西：
   - 站点 VPN（W45，`d1max-site vpn`）
   - 远程运维（W55）
   - 断网照样巡逻（`continue_if_safe`）

   做法：云服务器只开一个 UDP 端口（WireGuard），机器人和手机、电脑都拨进隧道。网页、MQTT、SSH 全走隧道，公网上看不到任何登录页。这是最快、也最安全的做法。
4. **第二期再把网页直接放公网。** 前提是加上二次验证，MQTT 改走 WSS 443。只在客户网络只放 TCP 443、4G 备用路由器也不行的时候才做。

## 1. 部署

### 1.1 云服务器

| 项 | 建议 |
|---|---|
| 机房 | **吉隆坡**优先（数据不出境，PDPA 最省事，见第 6 节）；没有合适的就用新加坡，到马来西亚 RTT 一般 10–20 ms |
| 规格 | 4 vCPU、8–16 GB 内存、100 GB SSD。站点出图要跑 MOLA 和真射线：商场那张在台式机 8 核上 41 秒、峰值内存约 1.9 GB；26 号那张更大，按 2–3 倍估 |
| 系统 | Ubuntu 22.04，跟现场站点一样。装 ROS 2 Humble 和出图组件（`install-site.sh --with-mapping`） |
| 域名 | 一个固定域名，比如 `poc.<公司域名>`，指向服务器的固定公网 IP |

### 1.2 端口

| 端口 | 第一期 | 说明 |
|---|---|---|
| UDP 51820（WireGuard） | **对外开** | 唯一对外的端口。不认识的包 WireGuard 一律不回，扫端口看到的是一个不回应的 UDP 口 |
| TCP 22（服务器 SSH） | 只在隧道里开 | 只认密钥、不认密码。云厂商的安全组也只放隧道网段 |
| TCP 8443（网页、API） | 只在隧道里开 | 跟现在一样：站点自签证书，App 钉证书 |
| TCP 8883（MQTT over TLS） | 只在隧道里开 | 机器人在隧道里连 `mqtts://172.29.70.1:8883` |
| 视频 | 只在隧道里 | 隧道里是 UDP，SRT 能过（11-04 隧道拓扑下 SRT 过不去的问题，换成 WireGuard 就没有了） |

**443 还是 8883，要不要改 WSS：** 第一期都走隧道，这个问题不存在。只有当客户网络连 UDP 都不放行（只放 TCP 443），4G 备用路由器（第 7 节）也装不了的时候，才需要第二期：

- `paho_transport` 加 `wss://`：paho 本身支持 websockets，改动小。
- 站点前面放 nginx 或 Caddy 监听 443，把 `/mqtt` 转给 mosquitto 的 websockets 口，网页也走 443。
- 视频要另外走 TCP，比如 WebRTC over TURN/TCP 或 HLS。**这一项是第二期里最大的工作量。**

### 1.3 现场专用的设置

| 设置 | 外网站点 | 现场站点（笔记本） |
|---|---|---|
| `NEXWAR_SITE_MQTT` | `mqtts://172.29.70.1:8883`（隧道地址） | `mqtts://<笔记本局域网地址>:8883` |
| `NEXWAR_SITE_NTP` | `172.29.70.1`（隧道里 UDP 123 能过）；或者干脆不设，机器人直接对公网 NTP | 笔记本地址 |
| `NEXWAR_ROUTES` | 不要：WireGuard 自己只把 172.29.70.0/24 走隧道 | 照现场拓扑填（比如 192.168.234.0/24 via R300S） |

### 1.4 两种站点怎么切换

机器人一次只认一个站点（注册文件和站点证书包是一对）。切换办法：

1. **每台机器人留两套配置**：`/etc/nexwar/env.cloud`、`/etc/nexwar/env.field`，加上各自的注册文件和证书包。`/etc/nexwar/env` 指向其中一套。
2. 切换 = 换指向，再重启代理。第一期在 Orin 上手动做：`sudo nexwar-site-switch cloud|field`，十几行的脚本，第一期要写的就这一个。第二期可以放进 App 的「换站点」。
3. 两边各绑一次机器人（W42 绑定）。机器人记录、地图在两边**不互通**：现场建的图要在外网站点上导入一次。站点有命令行的 `map import`：把笔记本站点上那一版的地图目录拷过去导入。网页上没有导出 / 导入按钮，要的话是个小工单。

**建议：** POC 期间外网站点是主站点；客户不让上外网的现场才用笔记本。建图都在笔记本上做，做完把地图导到外网站点。

## 2. 安全

- **对公网只有 WireGuard 一个口**（第 1.2 节）。管理后台、服务器 SSH、MQTT 都不对外。
- **二次验证**：站点现在只有账号密码。第一期靠「先要进隧道」挡住：每个人、每台机器一把 WireGuard 密钥，丢了就在站点上 `vpn remove`。第二期网页上公网之前，必须先加 TOTP 二次验证，这是一个新工单。
- **机器人身份**：W63 出厂证书已经在用（站点认机器人靠它，防克隆）。WireGuard 密钥只是通道，身份还是看 W63 证书和注册文件，两层都要对上。
- **更新**：服务器开 `unattended-upgrades`，只打安全补丁。站点程序走现在的签名升级包。
- **备份**：站点已有备份与恢复（W55）。每天加密备份一次，推到另一家的对象存储，留 14 天。
- **三把站点密钥怎么放**：
  - `secrets.key`、`evidence.key`：站点运行时要用，只能放在服务器上（`/etc/nexwar_site/`，root 0600）。服务器的盘开云厂商的加密盘。
  - `backup.key`：服务器上留一份（做备份要用），**台式机离线再存一份**（恢复要用）。服务器丢了，靠台式机那份解开备份。
  - **`factory.key`、`release.key` 永远不上服务器**，跟现在一样只在台式机上签。
- **服务器账号**：只开一个运维账号，密钥登录，sudo 要密码。不在服务器上放 GitHub 令牌这类东西。

## 3. 远程 SSH 进 Orin

**WireGuard 就够了，不用 Tailscale。** 原因：

- W45 已经把 WireGuard 做完了（`d1max-site vpn add robot <号>`），机器人每 25 秒保活，4G、Wi-Fi 来回切都不断。
- Tailscale 要经过它们的协调服务器，跟决策 71「不经第三方」不合。

**做法：** 机器人上装 `wireguard-tools`，`wg-quick@d1max` 开机自启。

- W45 原来设计跑在上装 RK3588 上；竞品上装没有 RK3588，就装在 Orin 上。
- 隧道里从站点或 N100 `ssh robot@172.29.70.1x`。
- 机器人对外不开任何端口，是它自己拨出来的。

**一键关掉：**

- 我们这边：站点上 `vpn remove robot <号>`，那台机器人的隧道当场失效。
- 客户那边（交付以后）：要的是「客户能关、我们关不掉也开不了」，开关必须在客户手里。所以交付时改成：
  - 客户自己的站点上有「远程维护通道：开 / 关」。
  - 关了就给机器人下命令停掉 `wg-quick@d1max-ops`，并禁止开机自启。
  - 这条运维隧道跟客户自己的站点 VPN 分开（另一个接口、另一把密钥）。

  **这是一个新工单**，POC 期间用不上。

**网页上的「远程运维」：** 有，是 W55 做的，但它**不是 SSH**。它是经站点给机器人下命令：

- 诊断快照、各服务日志、重启服务或整机、详细日志、对时、清理、续签证书。
- 站点那一侧：重启站点、测试推送、备份恢复、VPN 状态、运行指标。

在网页上的位置：

- 每台机器人的运维在「机器人」页每台下面一块，以及「诊断」页。
- 站点的运维在「系统」页下面的「远程运维」。
- 只有**管理员、工程师**看得到；要命的操作还要再输一次密码。

笔记本没找到，多半是登录的账号不是管理员或工程师，或者没往下翻到。下回现场用管理员账号核一下；真找不到，就是界面问题，我来改。

## 4. 断网时机器人怎么办

现在的规则（`nexwar_contract.policy`）：

| 任务 | 断网时 |
|---|---|
| 巡逻、派点（`patrol`、`goto`） | `continue_if_safe`：急停没按、定位正常、有控制权、电量够，就**接着走完这一趟**；否则停在原地等。只接受「中止」命令排队 |
| 遥控（`teleop`） | `stop_and_wait`：当场停车 |
| 中止（`abort`） | 机器人自己执行 |

断网期间的事件、照片进发件箱，恢复后补传，有退避加抖动（`upload_queue`）。代码是这样设计的，**但没在真机上完整测过**。

`docs/真机验证.md` 要加的几行：

1. 巡逻中途拔掉外网（机器人和站点之间断开），这一趟能走完；恢复后站点上这一趟的记录、照片都补齐。
2. 巡逻中途断网，同时让条件不满足（比如遥控器拿走控制权），机器人停在原地；恢复后能接着走或结束。
3. 断网期间机器人重启：恢复后状态正确，没有重复的「一趟」。
4. 断网超过 2 小时：发件箱不撑爆盘（已有上限），恢复后按顺序补传。
5. 外网站点恢复的时候 5 台机器人同时补传，站点不卡（已有抖动，要实测）。

## 5. 延迟和遥控

- 11-20 在局域网里就出现了「指令被判迟到」，走外网只会更多。
- 外网 RTT = 客户网络（Wi-Fi 或 4G，抖动 50–300 ms）+ 机房 10–20 ms。
- **巡逻、派点不受影响**：命令只是下达，机器人自己走。
- **远程遥控只适合慢慢挪**：近距离、窄处，还是要现场的人拿遥控器。

要加的提示（新工单，小）：

- 网页、App 的遥控页显示「当前延迟 xxx ms」。
- 超过 150 ms：提示「远程遥控延迟大，只适合慢速挪动」，速度自动压到「远程遥控速度」页设的慢档。
- 超过 400 ms，或丢包多：只许点动，不许按住连续开。

## 6. 数据和 PDPA

- 巡逻照片、录像里有人，属于个人数据。按马来西亚 PDPA：
  - 写清楚数据放在哪（哪个国家、哪家机房）、谁能看、留多久。
  - **机房放吉隆坡**，就不用处理跨境传输。放新加坡要按 2024 年修订后的跨境条款处理：对方法律相当，或者取得同意。**这一条请找懂 PDPA 的人确认一下，我不是律师。**
- 保留期建议：照片 30 天、报警证据 90 天、事件记录 1 年。这些在站点设置里定，POC 合同里写明。
- **录包不上云**（一天约 75 GB）：留在机器人上，或者 N100 / 笔记本在局域网里拉。上云的只有关键帧（建图要用，约 350 MB 一张，出完图按现在的规则留最近 5 份）。

## 7. 客户现场怎么上网

- 现在 R300S 用 `wifi_sta` 连客户 Wi-Fi。
- **建议带一台 4G/5G 路由器做备用**，要支持「有线或 Wi-Fi 优先、断了自动切 4G」。R300S 的上联插它，或者它本身就当 R300S 的上联。
- 4G 好处有两个：
  - 客户 Wi-Fi 不放 UDP 时，WireGuard 照样通，也就用不上第二期的 WSS。
  - 客户改了 Wi-Fi 密码，机器人也不会失联。
- 4G 没有公网地址不要紧：机器人是拨出去的，WireGuard 自己保活。

## 9. 机器人上的配置

- **日志重启后保留**：装机脚本已经写了 `/etc/systemd/journald.conf.d/nexwar.conf`（`Storage=persistent`，留 14 天、最多 500 MB，W55）。机器人下次开机先核一下：`ls /var/log/journal`，以及 `journalctl --list-boots` 能不能看到 11-20 那次。
  - **看得到**：11-20 的日志还在，按备忘取 16:30–16:50、17:30–18:06 那两段。
  - **看不到**：说明 C40221 当初装的版本没有这一项，补装上，11-20 的就丢了。
- **共享内存不清**：logind 补丁和 `loginctl enable-linger robot` 要补到 C40221、C40011 上（11-20 Nav2 失联的根因）。
- **WireGuard**：装 `wireguard-tools`，配置从站点 `vpn add robot` 拿，`wg-quick@d1max` 开机自启。

## 10. N100

- Ubuntu 22.04.5（HWE 内核）+ ROS 2 Humble，Intel 网卡。笔记本已经跟你确认过，没问题。
- 用途：
  1. **办公室的测试台**：在隧道里，有人帮忙给机器人开机，就能远程做基础测试（站起、趴下、派点、拍照）。
  2. **自动拉日志**：机器人一上线（在隧道里能 ping 通），就用 W55 的日志接口，或者经隧道 rsync，把 journald 和 `runs/` 拉回来。按机器人号、日期分目录。
  3. 需要时也能当办公室的本地站点（跟笔记本一样的角色），或者拉录包的中转。
- 它自己也是 WireGuard 的一个对端，固定地址，比如 `172.29.70.5`。
