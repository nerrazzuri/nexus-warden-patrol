# W43 公司后台：全貌规划

> 2026-11-26 用户：「W43 不是整套公司后台系统吗」「给一个规划，看看这公司后台需要有哪些功能」。
> 这份是**整套后台**的规划：有哪几块、各管什么、分几期、要用户定什么。
> 11-21 定的「一期只做证书」那份细方案在 `docs/公司后台-一期-方案.md`，就是这里的 A、I 两块。
> 还没定的地方都写在第五节，**用户定之前不开工**。
>
> 2026-11-26 用户：**一期也把站点健康（D）、发版升级（B）、日志故障（E）做了**。所以一期起站点就要连公司后台（第五节第 1 条按「要」算），后台放哪、公司能看什么要先定。

## 一、给谁用

**公司自己的人用**，不给客户用：

| 角色 | 在后台干什么 |
|---|---|
| 管理员 | 管账号、批准换主板、签作废名单、看操作记录 |
| 生产线 | 出厂登记、签出厂证书 |
| 工程师 | 申请解绑令、看站点健康、收故障包、远程协助（客户批准时） |
| 客服 / 销售 | 客户档案、保修、发版通知 |

**不在这里的**：安保公司一个人看多个站点的「集中监控中心」（V2 路标第五节）是**卖给客户的产品**，
要看画面和告警，跟公司后台的隐私底线正好相反，单独设计。云站点（11-12 先不做）也不在这里。

## 二、底线（已经定了的，后台必须守）

1. **画面、录像、地图、机器人位置、告警内容不出客户站点**（决策 71：站点走自己的 VPN，不经公司服务器）。
2. **公司在客户站点不留常驻账号**，工程师用业主开的临时账号（决策 73）。
3. **根钥匙永远离线**，只在台式机（以后是加密 U 盘）上（11-21）。
4. 客户可以要求站点只在局域网、完全不联网（决策 71）。**不联网的站点照样能用**，只是没有下面要连后台的那几项。

## 三、功能清单

「连站点」一列：要不要客户站点主动连公司后台。一期的 A、I 不连，B、D、E 要连。

| 块 | 功能 | 为什么要 | 连站点 | 期 |
|---|---|---|---|---|
| **A 设备与身份** | 设备登记表（导入出厂台账）、签出厂证书、签解绑令（一台、24 小时、一次）、中间钥匙、作废名单 | 现在都在台式机手工签，工程师在外面拿不到解绑令（W42、W63） | 不连 | 一 |
| **I 员工与审计** | 员工账号（密码 + 手机验证码）、角色、只能加不能改的操作记录 | 后面每一块都靠它 | — | 一 |
| **C 推送中转** | 站点把「有 P1 报警」交给后台，后台发到手机（FCM / 华为 / 极光） | **现在每个客户站点上都放着公司 Firebase 项目的服务账号私钥**（`docs/告警推送配置.md`）。这把钥匙管的是整个 Firebase 项目，不只是这个站点：一台站点主机被偷、被人拷走，钥匙就漏了；要换钥匙得一个个客户站点去换；Google 发现钥匙滥用可能停掉整个项目，所有客户一起收不到推送。每个新站点还要人手工放这个文件。中转以后钥匙只在后台，站点用自己的站点证书跟后台说话 | 连（只发：站点编号、报警编号、标题、级别） | 二（建议最先做） |
| **B 发版与升级** | 发行包仓库（代替现在的私有 GitHub 仓库）、站点来拉新版本、哪个站点在哪个版本、分批放、出问题停发 | 现在升级要人把包传到站点网页；客户多了做不过来 | 连（站点来问「有新版吗」，下载签名包） | 一 |
| **D 站点健康** | 心跳：软件版本、机器人几台在线、电量、故障码、磁盘、证书到期、上次备份时间 | 机器人坏了、盘满了、证书快到期，公司比客户先知道 | 连（只发状态，**不发画面、地图、位置、告警内容**） | 一 |
| **E 日志与故障** | 收日志（11-10「公司日志服务器，只收日志」）、客户点「发给厂家」上传故障包、站点被拒记录（`company-reports`）自动上来、故障单 / 返修记录 | 现在查问题要人去现场拷日志 | 连（日志要先去掉画面、地图、人名） | 一 |
| **F 远程协助** | 业主在站点上点「允许厂家协助 N 小时」，后台开一条限时的连接给工程师，到点自动断，全程记录 | 现在只能去现场或者让客户开 VPN 账号 | 连（只在业主批准的那段时间） | 三 |
| **G 客户与许可** | 客户档案、哪个站点哪台机器人归谁、保修到哪天；要的话再加许可、到期、功能开关 | 卖得多了要管保修、续费 | 许可要连 | 三 |
| **H 报表** | 公司内部：版本分布、故障率、哪种故障多；给客户的月报（覆盖率、告警数、处理时长）可以在客户站点自己生成，不经后台 | 改产品、做售后要数据 | 连（只用 D、E 的数据） | 三 |

## 四、公司能看到什么

> 2026-11-26 用户：**能看到不违反 PDPA 的**。下面按马来西亚 PDPA（2010，2024 年修订）的思路分三档。
> **我不是律师，上线前请懂 PDPA 的人过一遍这一节和合同条款。**

PDPA 管的是**能认出某个人的数据**（个人数据）。机器人的电量、版本、故障码认不出人，不归它管；
画面里有人、保安的名字、业主的电话就归它管。所以规则是：**后台默认只收认不出人的设备数据；
认得出人的，要么不收，要么客户点了、知道了才收，收了要管好、到期删掉。**

**第一档：照收（设备数据，认不出人）**

- 站点编号、软件版本、证书到期、上次备份时间、磁盘、站点主机温度和开机时长。
- 机器人序列号、型号、在线不在线、电量、故障码、急停次数、各服务起没起来。
- 告警只收**数量和级别**（今天 P1 几条、P2 几条），不收内容。
- 日志：上传前在站点上**先去掉**用户名、IP、地图坐标、人员检测框、文件路径里的名字，换成编号。

**第二档：客户点了才收（可能认得出人）**

- **故障包**：业主在站点上点「发给厂家」，先看到一句话「会发给厂家的有哪些、留 90 天」，确认了才传。
  故障包默认不带照片和地图；要带得业主再勾一次。
- **客户档案**（G，三期）：联系人姓名、电话写进合同，签合同时告知用途。

**第三档：不收**

- 实时画面、录像、截图、热像。
- 地图、路线、防区、机器人和人的位置。
- 告警的照片、内容、谁处理的。
- 站点账号、口令、保安和业主的手机号、推送令牌。

**管好、到期删**

- 收来的都写清楚：放在哪个国家哪家机房、谁能看（后台角色）、留多久。
- 保留：设备数据 1 年；去掉了个人信息的日志 90 天；故障包 90 天；操作记录 3 年。
- 后台被入侵、数据外泄：按 2024 年修订后的要求通知（先报主管部门，影响到人的通知本人），
  这套流程上线前写好。
- 客户合同里加一条数据处理条款，写上面这些。

## 五、要用户定的

1. **站点主动连公司后台**：☑ 11-26 定一期就做 B、D、E，等于定了「要连」。
   - 做法：只往外连（HTTPS），只传第四节第一档；第二档要业主点。客户可以在站点设置里关掉，
     关了以后升级退回手工传包，健康、日志就不传。
2. **公司能看什么**：☑ 11-26 用户「能看到不违反 PDPA 的」→ 第四节。上线前找懂 PDPA 的人过一遍。
3. **后台放哪台机器**：☑ 11-26 用户「需要租个 VPS」。
   - 机房**吉隆坡优先**：数据不出境，PDPA 最省事。之前比过 Hostinger KVM 2（吉隆坡，预付两年约 US$9/月，
     按月付 US$24–26）。
   - 没有合适的再用新加坡（Contabo 约 US$8–10/月，CPU 超卖；Vultr 约 US$24/月），要按跨境条款处理。
   - 哪一家、怎么付，开通前跟用户再对一次；一期 A、I 先在内网写和测，不用等 VPS。
   - 11-21「先不搞公网」说的是外网站点（`docs/外网站点-方案.md`），这台 VPS 只放公司后台，不放客户站点。
4. **要不要做许可和到期**（G）：机器人买断就不用；按年收服务费才要。
5. **远程协助要不要做**（F）：做的话安全要求最高，放最后。

## 六、分期

| 期 | 做什么 | 前提 |
|---|---|---|
| 一 | A + I：证书、解绑令、员工账号、操作记录（细方案 `docs/公司后台-一期-方案.md`）；D 站点健康、B 发版升级、E 日志故障（11-26 用户加进来，细方案待写） | 第五节第 1–3 条 11-26 已定；要租好 VPS、站点和机器人发一版会连后台的软件；A、I 可以先在内网做 |
| 二 | C 推送中转 | 站点已经连着后台，加这一项不难；要不要做看用户 |
| 三 | F 远程协助、G 客户许可、H 报表 | 第五节第 4、5 条定了；客户多了再说 |

每一期上线前做一次外审，重点看钥匙、权限、隐私。
