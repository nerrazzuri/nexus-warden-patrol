# W43 公司后台：全貌规划

> 2026-11-26 用户：「W43 不是整套公司后台系统吗」「给一个规划，看看这公司后台需要有哪些功能」。
> 这份是**整套后台**的规划：有哪几块、各管什么、分几期、要用户定什么。
> 11-21 定的「一期只做证书」那份细方案在 `docs/公司后台-一期-方案.md`，就是这里的 A、I 两块。
> 还没定的地方都写在第五节，**用户定之前不开工**。

## 一、给谁用

**公司自己的人用**，不给客户用：

| 角色 | 在后台干什么 |
|---|---|
| 管理员 | 管账号、批准换主板、签作废名单、看操作记录 |
| 生产线 | 出厂登记、签出厂证书 |
| 工程师 | 申请解绑令、看站点健康、收故障包、远程协助（客户批准时） |
| 客服 / 销售 | 客户档案、保修、发版通知 |

**不在这里的**：安保公司一个人看多个站点的「集中监控中心」（V2 路标第五节）是**卖给客户的产品**，
要看画面和告警，跟公司后台的隐私底线正好相反，单独设计。云站点（11-12 先不做）也不在这里。

## 二、底线（已经定了的，后台必须守）

1. **画面、录像、地图、机器人位置、告警内容不出客户站点**（决策 71：站点走自己的 VPN，不经公司服务器）。
2. **公司在客户站点不留常驻账号**，工程师用业主开的临时账号（决策 73）。
3. **根钥匙永远离线**，只在台式机（以后是加密 U 盘）上（11-21）。
4. 客户可以要求站点只在局域网、完全不联网（决策 71）。**不联网的站点照样能用**，只是没有下面要连后台的那几项。

## 三、功能清单

「连站点」一列：要不要客户站点主动连公司后台。**一期全部不连**。

| 块 | 功能 | 为什么要 | 连站点 | 期 |
|---|---|---|---|---|
| **A 设备与身份** | 设备登记表（导入出厂台账）、签出厂证书、签解绑令（一台、24 小时、一次）、中间钥匙、作废名单 | 现在都在台式机手工签，工程师在外面拿不到解绑令（W42、W63） | 不连 | 一 |
| **I 员工与审计** | 员工账号（密码 + 手机验证码）、角色、只能加不能改的操作记录 | 后面每一块都靠它 | — | 一 |
| **C 推送中转** | 站点把「有 P1 报警」交给后台，后台发到手机（FCM / 华为 / 极光） | **现在每个客户站点上都放着公司的 Firebase 服务账号私钥**（`docs/告警推送配置.md`）。哪个站点被拿下，就能给所有客户的 App 发推送。中转以后私钥只在后台 | 连（只发：站点编号、报警编号、标题、级别） | 二（建议最先做） |
| **B 发版与升级** | 发行包仓库（代替现在的私有 GitHub 仓库）、站点来拉新版本、哪个站点在哪个版本、分批放、出问题停发 | 现在升级要人把包传到站点网页；客户多了做不过来 | 连（站点来问「有新版吗」，下载签名包） | 二 |
| **D 站点健康** | 心跳：软件版本、机器人几台在线、电量、故障码、磁盘、证书到期、上次备份时间 | 机器人坏了、盘满了、证书快到期，公司比客户先知道 | 连（只发状态，**不发画面、地图、位置、告警内容**） | 二 |
| **E 日志与故障** | 收日志（11-10「公司日志服务器，只收日志」）、客户点「发给厂家」上传故障包、站点被拒记录（`company-reports`）自动上来、故障单 / 返修记录 | 现在查问题要人去现场拷日志 | 连（日志要先去掉画面、地图、人名） | 二 |
| **F 远程协助** | 业主在站点上点「允许厂家协助 N 小时」，后台开一条限时的连接给工程师，到点自动断，全程记录 | 现在只能去现场或者让客户开 VPN 账号 | 连（只在业主批准的那段时间） | 三 |
| **G 客户与许可** | 客户档案、哪个站点哪台机器人归谁、保修到哪天；要的话再加许可、到期、功能开关 | 卖得多了要管保修、续费 | 许可要连 | 三 |
| **H 报表** | 公司内部：版本分布、故障率、哪种故障多；给客户的月报（覆盖率、告警数、处理时长）可以在客户站点自己生成，不经后台 | 改产品、做售后要数据 | 连（只用 D、E 的数据） | 三 |

## 四、公司能看到什么（建议，等用户定）

| 能看 | 不能看 |
|---|---|
| 站点编号、客户名（手填）、软件版本 | 实时画面、录像、截图 |
| 机器人序列号、在线不在线、电量、故障码 | 地图、路线、防区 |
| 磁盘、证书到期、上次备份时间 | 机器人在哪、人在哪 |
| 有几条 P1（只有数量和级别，推送中转时临时经过标题） | 告警的照片、内容、谁处理的 |
| 客户点「发给厂家」主动上传的故障包 | 站点账号、口令、业主手机号 |

## 五、要用户定的

1. **站点要不要主动连公司后台**（二期 B、C、D、E 都靠它）。
   - 建议：**要**，只往外连（HTTPS），只传第四节左边那列。客户可以在站点设置里关掉；
     关了以后推送退回站点自己放私钥的老办法、升级退回手工传包。
2. **第四节那张表**：能看、不能看的清单对不对。这条牵涉 PDPA，最好让懂法务的人也看一眼。
3. **后台放哪台机器**（11-21 就没定）：办公室公网 IP / 租 Contabo / 只在内网 + VPN。
   一期只给员工用，内网 + VPN 也行；**二期站点要连上来，就得在公网上**，跟 11-21「先不搞公网」要一起重新定。
4. **要不要做许可和到期**（G）：机器人买断就不用；按年收服务费才要。
5. **远程协助要不要做**（F）：做的话安全要求最高，放最后。

## 六、分期

| 期 | 做什么 | 前提 |
|---|---|---|
| 一 | A + I：证书、解绑令、员工账号、操作记录（细方案 `docs/公司后台-一期-方案.md`） | 不连站点，内网就能做完测完；放哪台机器在上线前定 |
| 二 | C 推送中转 → D 站点健康 → B 发版升级 → E 日志故障 | 第五节第 1、2、3 条定了；站点发一版会连后台的软件 |
| 三 | F 远程协助、G 客户许可、H 报表 | 第五节第 4、5 条定了；客户多了再说 |

每一期上线前做一次外审，重点看钥匙、权限、隐私。
